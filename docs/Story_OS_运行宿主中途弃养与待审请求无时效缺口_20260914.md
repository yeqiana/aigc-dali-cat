## 三、三个独立缺口

### P1：宿主中途弃养，运行无自我恢复路径

`preimage-task-state.json`（`updated_at` 停在 18:07:04）：

```
4 个任务，全部 HOST_ACTION_REQUIRED
  preimage-character_finalize-dc888d      req=preimage-fece9320097023f6
  preimage-environment_prepare-dc888      req=preimage-33a8fbc1c544231d
  preimage-world_prepare-dc888dc29b3      req=preimage-1c06c42b329ec0cc
  preimage-visual_narrative_prepare-      req=preimage-31222fc675980644
snapshot_id = dc888dc29b31e9e0324c8e2425e987618e3f288bcf23c48143ca427ba211f4ac
```

这 4 个是**宿主活**。DAG 在等宿主来干，而宿主（DevSpace agent）18:12:37 之后
再没看过剧集一眼。**没有任何机制会把它的注意力拉回来**——除它自己决定回头。
即使它随后醒来，其待办也是「跑那个 18:13:55 没跑的测试」，而非剧集。

> **旁证（一次性质疑，未决）**：6 组 `Codex\runtimes\cua_node\server.mjs` 进程对，
> 最后一对起于 **18:17:48**，晚于日志末条（18:13:55）。这与「codex 侧已完全停止」
> 不符，但也可能是 Codex GUI 自身的活动，**不足以推翻 P1**。此处如实记录，不作结论。

### P2：引擎三处投影自相矛盾

同一时刻三个权威来源互相打架：

| 来源 | 时刻 | 说法 |
|---|---|---|
| `meta/runtime/reviews/story-semantic-request.json` | 18:06:05 | `AWAITING_PRODUCT_REVIEW`（attempt 2） |
| `meta/episode-state.json` | 18:06:49 | "Story Critic PASS" |
| `meta/runtime/next-action.json` | 18:07:04 | `PREIMAGE_TASK_SET` |

补充事实：attempt 2 的候选人文件 `meta/.story-semantic-review.candidate.json` **从未存在过**；
`story-semantic-review.json` 是 18:00:17 的 attempt 1。即 **attempt 2 是一张没有候选人的待审单**。

### P3：`pending_product_review()` 无时效上界，且豁免清单不覆盖 `story-semantic`

`episodes/_system/next_action.py`：

- L50 `pending_product_review()`：`status == "AWAITING_PRODUCT_REVIEW"` 即入列（L78），
  **没有任何时间上界**，按 `created_at` 取**最旧**一条（L82）。
- L74-75 的陈旧豁免只覆盖 `visual-lock-baseline` / `visual-lock` / `visual-profile-legacy`，
  **不含 `story-semantic`**。

**未提交改动引入的新风险**：工作区中 `next_action.py` 有一处**未提交**改动，
把 `PRODUCT_REVIEW` 的早返回从下游前移到 L269-272（紧随 hard_stop 之后），理由是
「新鲜的待审文本评审必须压过 PREIMAGE 新鲜度」。该推理本身成立，但与 P3 叠加后：

> **只要盘上存在一条无法完成的 `story-semantic` 请求，剧集就被永久钉在 `PRODUCT_REVIEW`。**

这不是理论风险：尸解仙 盘上那条 18:06:05 的 attempt-2 请求**今天就在**，
重跑到同一位置必然踩到。该改动**未提交、未跑测试**（agent 改完就静默了）。

另：该请求自身要求
`fresh_product_review_turn_required: true` + `devspace_bounded_fallback_allowed: false`
+ `local_codex_review_allowed: false`——一个**新鲜的隔离 WORK 回合**。
宿主能否取得该回合未经验证；这可能是 agent 当时真正卡住的点。

**一条被本次事件推翻的经验**：原先的判据是「`edit` 之后没有 `bash` = 它正在生成下一步」。
本次静默 600s 使该判据的结论反转——它不再是「正在生成」，而是「这一轮没回来」。
**判据需要配一个时间上界**，建议取运行内历史最长间隔的 2.5 倍（约 220s）为界。

## 六、影响与未决

**影响**：尸解仙 本次运行作废，需重新发起。重跑前必须先处置 P3 的未提交改动，
否则会再次被同一张无候选人的 attempt-2 待审单钉死。

**未决**：

1. `story-semantic` attempt 2 是否应当计数？若属陈旧残留，应加时效上界或显式作废。
2. 宿主取得 `fresh_product_review_turn_required` 隔离回合的实际可行性。
3. `pending_product_review()` 是否应引入统一时效上界（而非继续扩充豁免清单——
   扩充清单是放宽护栏，且键粒度会连带放行）。
