# 1. 一句话目标

本轮不是继续增加新的 Runtime、Adapter、Phase 或治理模块，而是把 Story OS 收敛成一条真实、可验证、可恢复的生产链：

```text
用户请求
  ↓
story_os.py
  ↓
唯一 Driver
  ↓
Production Kernel（episodes/_system）
  ↓
WORK / CODEX_IMAGE / CODEX_VISION
  ↓
Gate / Evidence
  ↓
Release
```

并确保：

> **配置写了什么、文档说了什么、实际谁在消费、最终发生了什么，四者一致。**

本轮不以“字段正确”“报告写已完成”“doctor 为绿”作为最终验收标准，必须以**真实执行行为**作为验收依据。

# 2. 当前问题总览

当前 Story OS 不是一个单点故障，而是以下几类问题叠加：

| 类别 | 当前表现 | 风险 |
|---|---|---|
| 生产归属双轨 | `primary_runtime=V3_RUNTIME`，但生产仍由 `episodes/_system` 执行，生产侧无消费者 | 迁移状态失真 |
| Driver / Step Engine 混淆 | `runner / run / dag run / runtime_dag.py` 多入口都像“启动生产” | 容易出现无人持续驱动 |
| 长任务生命周期断裂 | Story OS 单步可运行 3600s，但宿主工具 300s 即终止 | Driver 被杀、Codex 孤儿任务白跑 |
| Detached 能力未产品化 | 当前依赖 `.storyos_cache/dag_detach.py` 旁路 | 可用但不可维护、不可作为正式生产能力 |
| Resume/Attach 缺失 | Codex task result 已落盘，但新的 DAG 不会领取旧结果 | 重跑烧额度、状态不推进 |
| PREIMAGE 注册表漂移 | task type 与 `stage_read_sets` / `STEP_DIRECTIVES` 步骤名不一致 | 确定性崩溃 |
| 配置账实不符 | 多项配置只有声明、没有消费者，或多个文件值冲突 | 看配置无法推导真实行为 |
| Product Review 残留 | 已经回答过的 review request 可能继续处于 pending | 剧集永久钉死 |
| 治理文档膨胀 | docs/reports 数量接近生产代码模块数量 | 状态源、历史证据、当前方案混淆 |
| Canonical 问题账本漂移 | 新问题继续独立建 MD，未立即并入总清单 | “统一问题源”再次失效 |

# 3. 本轮架构口径冻结

在修复代码前，先冻结以下口径。后续实现、测试、文档均不得再建立相反叙事。

## 3.1 Production Kernel

当前且本轮继续使用：

```text
episodes/_system
```

作为 Story OS 的**唯一 Production Kernel**。

它负责：

- Story / Storyboard
- PREIMAGE
- Frame Contract
- Visual Lock
- Image Queue / Scheduler
- Review
- Gate
- Episode State
- Production Ledger
- Release

本轮**不把上述能力重新复制到 `platform/`**。

---

## 3.2 Platform 定位

`platform/` 定位为：

```text
Platform Services / Control Plane
```

负责：

- MySQL / Redis Repository
- Event / Projection
- Agent / Skill Registry
- Memory
- API / Console
- Canary / Operations
- Migration evidence
- Observability infrastructure

它不是第二套 Production Kernel。

---

## 3.3 Runtime 拆分

以后不要再用一个 `V2_RUNTIME / V3_RUNTIME` 字段试图描述整个系统的实际执行权。

真实执行职责至少拆为：

```text
Production Kernel
= episodes/_system

Driver / Lifecycle Host
= runtime_driver
  + persistent_runner_daemon
  + episode_runner

Scoped Agent Runtime
= WORK / WEB / CODEX（按 runtime route）

Image Runtime
= CODEX / PRODUCT_RUNTIME

Vision Runtime
= CODEX_VISION

Review / Governance Runtime
= WORK（及受控 isolated critic）
```

这里必须区分“**谁持续驱动流程**”与“**谁执行模型工作**”：Driver 是生命周期 owner；WORK/CODEX/WEB 是执行/宿主 runtime，不得再把 `Host Runtime = WORK` 当成 resident Driver 的同义词。

如果保留 `primary_runtime`，它只能有明确、真实的业务含义；否则应降级为历史迁移证据，不得继续作为“生产已接管”的完成标志。

---

### P0-B 单一 Driver 收敛 `[✅ 核心已落地]`

正式语义冻结为“**一个逻辑 Driver、两种启动方式、一个 Episode 一个 owner**”：

```text
前台调试 / 观察：
story_os.py runner <episode>

正式 detached 生产：
story_os.py driver start <episode>
```

两者必须进入同一 resident Driver 语义、同一 owner lock、同一 heartbeat / next-action / DAG 执行链；`driver start` 不是第二套 Driver。

其他入口：

```text
story_os.py run --full-auto
```

= 有界排空；可以推进，但遇 Host Action 可返回，不代表常驻 Driver。

```text
runtime_dag.py / story_os.py dag run
```

= Step Engine，只执行步骤，不是长期生产 Driver。

必须做到：

- 文档、模块索引、next-action、health 口径一致；
- 自动化测试阻止 DAG 再被登记为常驻入口；
- 一个 Episode 同时只能存在一个有效 Driver owner。

---

### P0-C 长任务正式 Detached / Resume `[✅ 实现与 >300s 专项验收均已落地]`

当前 `.storyos_cache/dag_detach.py` 只能作为实验验证，不得成为最终产品依赖。

正式能力必须具备：

1. Story OS 官方入口可 detached 启动长任务；
2. Driver 生命周期不受宿主单次 300s tool call 限制；
3. stdout/stderr / exit code 可持久化；
4. 可查询当前 Driver 是否存活；
5. Driver 异常消失后可安全恢复；
6. 不以全局 `taskkill /IM codex.exe` 作为恢复方式。

---

### P0-D Codex in-flight task Resume / Attach `[✅ 实现与契约测试已落地｜🟡 真实中断回归待完成]`

必须解决：

```text
Driver 死亡
→ Codex 继续跑完
→ task-results/<request_id>.json 已存在
→ 下一 Driver 却重新发新 request_id
```

目标行为：

```text
Step 开始
→ 写入 in_flight_request_id
→ Driver 中断
→ Codex 完成并落结果
→ Resume
→ 优先读取原 request_id
→ rc=0 + 结果完整 → 采纳旧结果
→ 不再重复调用 Codex
```

安全原则：

- 只采纳明确完成且完整的结果；
- rc != 0 不直接当成功；
- request fingerprint / source SHA / step 必须匹配；
- 若原任务仍运行中，不得无条件再提交同一任务形成双执行。

---

### P0-E PREIMAGE Task Registry 对齐 `[✅ 已完成，Canonical W-102]`

当前确定性缺陷：

```text
PREIMAGE_ENVIRONMENT_PREPARE
PREIMAGE_WORLD_PREPARE
PREIMAGE_VISUAL_NARRATIVE_PREPARE
```

与 `stage_read_sets` / `STEP_DIRECTIVES` 注册名称不一致。

修复原则：

- 由一个单一映射定义 `task_type → canonical_step_name`；
- runtime_dag 不再字符串拼接猜步骤名；
- 启动时自检：所有 PREIMAGE task 必须同时存在 read-set、directive、executor 注册；
- 缺任意一个时在任务启动前失败，而不是运行 20 分钟后才失败。

---

### P0-F Product Review 残留自愈 `[✅ 核心已完成]`

解决：

```text
旧 attempt 已完成
但 alias / attempt-2 仍 AWAITING_PRODUCT_REVIEW
→ next_action 永久 PRODUCT_REVIEW
```

必须满足：

- 同 frozen source 已有有效 FINALIZED PASS 时，不重复阻塞；
- source SHA 改变后必须允许新的 review；
- FAIL 后 revise → attempt 2 的合法路径不得被误杀；
- production repair / caption audit 等“FINALIZED 不代表 PASS”的 review 类型不得被错误 suppression；
- suppression 必须可观测，不得静默吞请求。

---

### P0-G Product Review Request Lifecycle `[❌ 漏项补充，Canonical W-32]`

P0-F 只解决“已经被旧 FINALIZED PASS 回答过、却仍残留 AWAITING”的重复请求；它**不能**解决真正无人处理的 Review request 永久等待问题。

当前开放事实：

```text
AWAITING_PRODUCT_REVIEW
→ 没有人处理
→ Driver / Host 重启
→ 数小时 / 数天后仍 AWAITING
→ Episode 永久被 PRODUCT_REVIEW 钉死
```

必须补齐 request-level lifecycle，至少支持：

```text
AWAITING_PRODUCT_REVIEW
  ├─→ FINALIZED
  ├─→ EXPIRED
  ├─→ CANCELLED
  └─→ SUPERSEDED
```

约束：

- 超时/过期 **绝不能等价于 PASS**；
- source SHA 已变化时，旧请求应可 `SUPERSEDED`，新 source 建新 attempt；
- Driver 恢复后必须能区分“仍值得等待”与“已失效”；
- expiry/cancel/supersede 必须进入 next-action / evidence / audit；
- 不允许通过“忽略所有旧 pending”来伪造恢复。

# 16. 最终完成定义（Definition of Done）

本方案全部完成，不等于“所有 Story OS 历史问题都解决”。

本轮 DoD 只要求：

```text
1. 架构身份不再自相矛盾；
2. 一个 Episode 只有一个 Driver；
3. 长任务可活过宿主 300 秒限制；
4. Driver 中断后已完成模型任务可被重新领取；
5. PREIMAGE 不再因注册表漂移确定性崩溃；
6. stale/redundant Product Review residue 不再永久钉死流程，且真正无人处理的 request 具备 expiry/cancel/supersede 生命周期；
7. 关键配置的声明值与真实消费者一致；
8. 新问题全部进入 Canonical；
9. 尸解仙真实恢复链验证通过；
10. 最终连续 3 篇真实生产无需工程修代码救场。
```

三个完成状态**独立判定，不再绑成一个总开关**：

```text
ARCHITECTURE_CONVERGED
= Production Kernel / Platform / Driver / Step Engine 角色不再自相矛盾，ownership 不再以账面字段冒充执行事实，配置 authority 完成必要收敛。

RUNTIME_RECOVERABLE
= Detached 330s 实测通过 + Driver 中断 Attach/Resume 真实验证通过 + Product Review request lifecycle（W-32）可恢复；若 W-03 仍无宿主重启恢复能力，只能标“进程内可恢复”，不得标无人值守 recoverable。

PRODUCTION_CLOSURE_VERIFIED
= 连续 3 篇真实生产到 PUBLISH_READY，0 工程救场，至少 1 篇经过受控 Driver 故障注入，且运行证据完整。
```

允许出现：

```text
ARCHITECTURE_CONVERGED = PASS
RUNTIME_RECOVERABLE = PENDING
PRODUCTION_CLOSURE_VERIFIED = PENDING
```

不得因为最终三篇尚未完成，就把已经独立验收通过的前置层级重新改回失败；同样也不得用前两层 PASS 冒充最终生产闭环 PASS。
