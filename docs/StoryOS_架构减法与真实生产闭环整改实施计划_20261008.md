## 1. 四槽位持续滚动队列

| 槽位 | 当前第一项 | 后续滚动 | 完成定义 |
|---|---|---|---|
| A／P0 生图 | 核对 Codex native-only 和 capability attestation；定位正式生产 preflight 与受限 canary 的边界 | 原生工具真实证明、图片生成记录、恢复队列与 M00 | 真实原生 session/tool 证明、合法图像文件及 SHA-bound receipt；不能证明则明确外部 blocker 而不是空等 |
| B／P0 Controller | 处理 source prompt 年龄漂移与旧 SUCCESS receipt 复用冲突 | 校验版本指纹、旧证据废弃与有界重建、回归测试 | 不修改旧回执；旧 invalid result 不能假装成功，重新请求可正常进入 Validated Payload |
| C／P1 调度 | 统一 effective-config、并发、retry 注释；明确 WAIT/BLOCKED/FAILED 真实语义 | next_action 直达可执行恢复动作，简化悬挂请求 | 文档/代码同一口径；无 worker 时不报告 RUNNING；下一动作与阻断原因可查询 |
| D／P1-P2 瘦身 | 审查 LOCAL MySQL/Redis/文件 Authority 及 SQLite 方案并界定风险 | Release/Caption Review 限制上下文与超长 span cleanup；分阶段迁移 | 不触碰现有数据；形成可回滚迁移切片、可测量的 Review/DB 改善 |

**滚动规则**：始终保持最多 4 个独立在途修复任务；完成一项即补入下一项；同一文件禁止跨槽同时写。Image Scheduler 的真实图片 `max_inflight_images` 是**不同维度**，按生产配置有效值执行，不把修复并发和图像并发混为一谈。

## 2. 可执行阶段与验收关卡

### P0-1 保住执行来源并查清工具能力
1. 只读 `git status`、真实 runtime.env **存在性**、现行 MySQL Authority 与 Episode 事实位置；禁止根据 Git 文件缺席断定 Stage 丢失。
2. 核验 `codex_user_runner.resolve_provider_transport` ：默认 `native_codex`；图片 explicit non-native 一律 reject；真实 Codex 会话与画像工具需要**正证据**，不能只读模型 catalog 推断工具可用。
3. 检查 Phase5A 有界 canary 已存在的签名 grant、Attempt 限额。允许它在精确授权的一帧下进行真实能力探测，但绝不把该特例放大为普通 Batch bypass。
4. 输出 `READY / BLOCKED:<code> / HOST_ACTION_REQUIRED` 和下一修复动作；不得循环消耗失败 Attempt。
5. 首张正式 RAW 必须可解码，尺寸/画幅与 Frame Contract 一致，Receipt 与图片 hash 能验算，然后才能推进 M00 gate。

### P0-2 Controller Cache 正确性
1. Controller input_fingerprint 包含检查策略的版本或显式 validator identity。
2. 对已存在的旧回执做语义校验：错误时 `SUPERSEDED/NOT_REUSABLE` 并创建新的、不覆盖历史的 Controller request；不可直接永久抛错。
3. 双向锁定 `source_scene_prompt` 可见年龄/时间线，仅在存在清晰约束时拦截，避免误伤非人物场景。
4. 保留拒绝/替代证据；测试 47/56、同龄/无年龄、缓存命中、历史回执不覆盖、幂等重试。

### P1 控制面和回收
1. 清晰区分 Stage Authority、任务执行态、执行回执、当前投影。流程正常 Host WAIT 不应算 ACTIVE，失败终态不能残留 RUNNING。
2. 修正 `START_HERE` 里 Worker 默认值，固定有效配置读取；修正注释与实际 retry budget 不一致，并暴露 effective-config / 解释来源。
3. 缩窄 Release/Caption 审核为明确对象、合同、最终图片；避免全仓探索。用户 current SHA acceptance 应 cancel/supersede 重复等待，但不得绕过必需的最终语义审核。

### P2 LOCAL Runtime 轻量化
1. 先仅审计：`runtime.env` 指向的真实数据库类型及可连接性（凭据不打印）；MySQL Authority / Redis hot state / JSON history 各自责任；备份和回滚计划。
2. 逐步按 Repository Provider 切换，SQLite WAL、busy_timeout、单写事务、CAS 与恢复测试；图片/大 immutable 文档仍在磁盘。
3. 未完成对账前，不能停止 MySQL、删除持久化表或设置“SQLite 为唯一 Authority”。
4. 迁移完成且验收后才能删除 LOCAL legacy 分支，不能把 SQLite/MySQL/JSON 再做一套永久三态。
