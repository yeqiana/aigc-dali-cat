# StoryOS 双作品生产入口只读预检（2026-10-10）

在本地 canonical 主工作区执行（未使用 Fixture，也未启动 paid worker）：

```powershell
python scripts/storyos_multi_episode.py plan `
  --episode "episodes/00_独立篇/04_未交的答卷" `
  --episode "episodes/00_独立篇/05_五十亩山地之后"
```

### 实际命令结果

- 两部 Episode 均存在，正式 Driver 的只读状态均为 `NEVER_STARTED`、`liveness=DEAD`。
- `global_max_inflight_images=5`、`observed_busy=0`、`observed_available=5`，并明确标记 `advisory_snapshot_only=true`。
- `model_calls=0`、`authority=DIAGNOSTIC_ONLY`，没有启动图像生成、没有新 Claim 或阶段迁移。

### 不能凭这些数据推断

- `NEVER_STARTED` 是**当前 Driver 实例视角**，不是 Episode 从未制作过的历史结论；旧作品仍可能有 JSON/MySQL 的审核、Revision、Attempt 和图片数据。
- 快照不是硬性的图片并发锁；真实图片由 Gateway 的跨工作树 permit 做执行前仲裁。
- 本命令只读取 Driver 状态和资源快照，不核验 MySQL Attempt UNKNOWN、Release 权威、候选 SHA、全部图片是否一致，也不自动取得生产许可。

### 最小安全原则

只允许 `plan` / `status` 只读预检；`start` 必须由操作者明确确认 `--ack-real-production`，且各 Episode 正式 Driver 仍须独立执行全部 Gates。不引入第二套多作品调度器，不修改 5 图全局容量。
