# Story OS 本地视觉提速提质实施方案

> 日期：2026-09-25
>
> 目标：在不削弱 Story / Frame Contract / Final Critic / Evidence Gate 权威的前提下，用本地确定性算法与开源模型把明显坏图、重复图、返修越界、身份/姿态/物体异常尽量前置发现，把昂贵的 Vision/LLM 调用集中到真正需要语义判断的帧。

## 0. 成功口径

第一阶段不追求“整集直接 2 倍快”，而追求：

- Vision call reduction >= 40%
- Review wall time reduction >= 40%
- Repair / re-review cycles reduction >= 20%
- 端到端 Episode wall time reduction 目标 25%~40%
- Vision token reduction 目标 40%~60%
- 重复/近重复帧漏检下降 >= 80%
- Repair 非目标区域漂移下降 >= 50%
- 角色/连续性机械异常漏检下降 30% 左右

任何“提速 / 省 token / 提质量”结论都必须来自真实新 Episode 跑批，不允许用离线回放替代生产验收。

## 1. 原则

1. **不建立第二状态机。** 本地算法只输出派生 evidence / triage，不修改 Episode stage。
2. **不越权替代语义 Critic。** 情绪、叙事张力、悬念泄露、表演是否成立等仍由正式视觉 Critic 判断。
3. **只对确定性硬故障自动阻断。** 例如图片不可读、正式画布不匹配。模糊、重复、身份漂移、姿态异常等首轮先标 SUSPECT。
4. **越贵的本地模型，运行的帧越少。** 使用漏斗而不是所有模型对所有帧全跑。
5. **所有诊断必须 SHA 绑定。** 旧诊断不能对新像素生效。
6. **Fail-soft 优先。** 本地模型缺依赖/初始化失败默认退回正式 Critic；不能因为辅助模型坏了卡死主生产。
7. **统一证据入口。** 派生诊断优先写入 `meta/runtime/diagnostics/`，不成为发布权威。

## 2. 目标架构：Local Visual Triage Runtime

```text
Image Generated
      |
      v
Technical Gate
  - decode / canvas
  - brightness / entropy / edge proxy
  - perceptual hash
      |
      v
Structural Triage
  - OCR / YuNet
  - SFace
  - Pose
  - Grounding DINO
      |
      v
Continuity Triage
  - perceptual fingerprint
  - DINOv2 embedding
  - identity / adjacent-frame drift
      |
      +---- low risk ----------+
      |                        |
      +---- suspect/high risk  |
                |              |
                v              |
           Vision Critic <-----+
                |
                v
            Final PASS
```

Repair 独立增加：

```text
source candidate + repair output
        |
        v
Repair Integrity
  - exact hash
  - pHash/dHash
  - pixel delta / bbox
  - later: SAM2 mask + LPIPS/SSIM
        |
        v
SUSPECT -> Critic priority
```

| `repair_integrity.py` | Repair 前后像素变化、no-op/异常漂移提示 | 首轮只 SUSPECT | ✅ 已接主流程 |
| `local_visual_triage.py` | 统一入口、证据写入、queue 摘要 | 仅硬技术故障 | ✅ 已接 image_scheduler + batch_scheduler |

| 模块 | 建议技术 | 作用 |
| --- | --- | --- |

## 4. 3 槽位滚动规则

始终保留三个并行槽位：

- **Slot 1 — Technical / Duplicate**：硬技术门禁、pHash、重复图、低信息量预警。
- **Slot 2 — Repair Integrity**：Repair 前后完整性，后续升级到 mask + SSIM/LPIPS。
- **Slot 3 — Continuity / Semantic Triage**：视觉指纹基础 -> DINOv2 -> SFace/Pose/Object。

每个槽位只有满足以下条件才进入下一层：

1. 单元测试通过；
2. 已接到正式 scheduler/review 入口；
3. Evidence SHA 绑定；
4. 不改变 canonical stage authority；
5. 没有真实生产数据前只标“接入”，不标“提速完成”。

## 5. Phase A 证据格式

每次图片生成后写：

`meta/runtime/diagnostics/local-visual-triage/<queue_item_id>.json`

最低字段：

- candidate SHA256
- frame / queue item / kind
- technical status
- perceptual fingerprints
- duplicate candidates
- repair integrity（repair 时）
- `PASS / SUSPECT / FAIL / UNKNOWN`
- `block_commit`
- issue codes
- generated_at

这些文件是 derived evidence，不是 Stage Authority。

## 6. 自动阻断边界

Phase A 只允许以下自动阻断：

- 图片无法解码；
- 输出尺寸与当前 Episode 正式 canvas 不一致。

以下全部只标 SUSPECT，不自动判内容失败：

- 极暗 / 极亮；
- 低熵 / 低边缘细节；
- exact / near duplicate；
- Repair no-op；
- Repair 大面积漂移；
- 后续 SFace / DINO / Pose / GroundingDINO 异常。

## 7. 生产 KPI 采集

每个真实 Episode 至少记录：

- generated_frames
- local_triage_pass / suspect / fail / unknown
- exact_duplicate_count
- near_duplicate_count
- repair_noop_count
- local_triage_elapsed_seconds
- vision_call_count
- vision_elapsed_seconds
- vision_tokens
- repair_count
- re_review_count
- review_wall_seconds
- episode_active_wall_seconds

正式 A/B 验收至少 3 个新 Episode，且同类题材/帧数尽量一致。

## 8. 回滚

- 总开关：`production.local_visual_triage.enabled=false`
- 硬阻断开关：`production.local_visual_triage.hard_failures_block_commit=false`
- 关闭后仍保留正式 Critic / Evidence Gate 原链路。
- 派生诊断可安全删除/重建，不得影响已有 PASS 权威。

## 10. 完成定义

这项优化只有在真实生产达到以下最低结果后才能关账：

```text
Vision calls       -40% or better
Review wall time   -40% or better
Repair cycles      -20% or better
No increase in false PASS
No regression in final evidence gate
```

如果本地模型增加的 wall time 高于节省的 Critic 时间，或 SUSPECT 率过高导致更多人工/LLM复核，则回滚对应槽位，不继续堆模型。
