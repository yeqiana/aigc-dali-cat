# Story OS 开源算法与工具分层选型

状态：分阶段实施中。RapidOCR 与 YuNet 已进入审核入口，Pillow 字幕像素完整性检查与严格本地字幕分流已接入；SFace 仍离线。真实 Episode 的净提速和质量对照尚未验收；文本检索评估后暂缓引入。日期：2026-09-23。

## 1. 目的与边界

本文件把可用于节省模型调用、输入 token 或生产等待时间的本地能力，映射到当前 Story OS 执行链。它不是创作规范、生产配置、门禁或第二状态机。正式创作规范仍以 `standards/制作规范_正式版.md` 为准；正式阶段仍以 Episode 的 `meta/episode-state.json` 为准。

当前有效配置见 `config/storyos.yaml`：整体 Runtime 优先 `CODEX`，图片最大并发 5，实际像素审核使用独立 Codex Vision critic。`runtimes/runtime-dag.json` 描述 CREATIVE_STORY → PREIMAGE_COMPILE → VISUAL_LOCK → PRODUCTION → RELEASE。历史入口文档中的 WORK/max 3 口径不能代替当前配置。

## 2. “属于哪一层”：术语与调用关系

```text
Runtime DAG / 调度层
  → Story OS Python 业务模块：编排、合同、SHA、门禁
    → 本地算法工具层：OCR、人脸检测/特征、文本检索、图像几何
    → 模型执行层：创作、生图、实际像素与语义审核
  → 派生诊断/证据层：工具结果、耗时、来源 SHA
  → 现有正式门禁和 Episode 状态
```

| 名称 | 本文含义 | 是否适合成为 Agent Tool / MCP Tool |
| --- | --- | --- |
| 开源库/模型 | RapidOCR、OpenCV YuNet/SFace、BGE 等，是 Python 进程里的实现依赖 | **默认不单独暴露**。它们不是 Story OS 的 Agent、Skill 或 Runtime。 |
| 本地算法 Tool | Story OS 封装的窄接口，例如 `inspect_caption_obstruction(image, layout)`、`detect_faces(image)`、`retrieve_similar_stories(text)` | 只有多个 Runtime/Agent 都需要调用、并具备稳定输入输出和权限边界时，才考虑注册为 Agent Tool；跨进程或跨宿主复用时再考虑 MCP。 |
| 业务模块 | `caption_image_audit.py`、`visual_lock_baseline_gate.py` 等，负责决定何时调用 Tool、怎样处理失败 | 不因引入算法而迁移目录或改为新框架。 |
| 派生诊断 | 绑定源图片/合同 SHA、工具版本、模型版本和置信度的建议或告警 | 可缓存、可重建；**不授予 PASS**，不直接推进 Episode 状态。 |
| 正式审核/门禁 | 当前 Critic、Evidence Gate、Snapshot 校验等 | 仍是现有权威路径；本选型不更改其批准语义。 |

“Tool”表示 **Story OS 可调用的本地能力**，并不等于必须建 MCP Server。只有算法需要跨 Runtime 共享时，才按已有 `docs/architecture/Story_OS_MCP与Skill体系设计_V1.0.md` 的平台设计评估 MCP 暴露；本次试点优先 Python 内部调用，减少部署和协议开销。

## 3. 逐步骤选型

| 步骤 | 现有位置 | 推荐能力及层次 | 用途与预期收益 | 不可替代的判断 / 状态 |
| --- | --- | --- | --- | --- |
| 请求解析与恢复 | `runtime_dag.py`、增量计划、SHA 证据 | **不新增组件**；现有确定性业务模块 | 复用有效证据，避免重复模型调用。 | Runtime Request 与正式阶段权威不变。 |
| 选题与去同质化 | `concept_ambition.py`、最近作品/账号学习索引 | `BAAI/bge-small-zh-v1.5` 本地向量模型 + 余弦相似度，属**检索 Tool**；精确词检索可用 SQLite FTS5 | 找出相似故事、异常机制和结尾，只向 critic 提供少量相关历史材料；候选上下文缩短后才可能省输入 token。小样本可内存遍历，不建向量数据库。 | 相似度只是检索和提示；不能自动否决创意或绕过 Concept Ambition。FTS5 默认中文分词需实测，不能照搬英文词搜索。 |
| 故事、分镜、帧合同 | `execution_capsule.py`、`prompt_package.py`、`frame_contract.py` | **保留现有合同/派生缓存**，不引入本地小语言模型 | 先测重复上下文量，再决定是否进一步裁剪提示词。 | 不能遗漏主规范、角色/环境/帧合同中的必读约束。 |
| Visual Lock baseline 与角色切图 | `visual_lock_baseline_gate.py`、`character_visual_contract.py` | OpenCV **YuNet** 人脸检测，属**像素预检 Tool**；Pillow 继续裁切 | 给出候选人脸框、面积和可见性告警，减少模型处理纯坐标问题。 | P01/P02 身份归属、真实感、构图与母版准入仍由现有审核确认。原有裁切是本地计算，本身不是 token 大头。 |
| 人物跨帧连续性 | `identity_continuity.py`、`reference_arbitrator.py` | OpenCV **SFace** 特征比对，属**像素预检 Tool**；依赖 YuNet 的脸框 | 以母版图和后续帧比较，优先提示明显漂移帧，减少晚期返修。 | 侧脸、遮挡、画风变化会误报/漏报；分数不能直接 PASS/FAIL。 |
| 生图与 Normalize | `image_scheduler.py`、`batch_scheduler.py`、`canvas_normalize.py` | **保留现有 Pillow、尺寸/比例/SHA 校验** | 技术性校验已在本地完成；不建议为同一目的增加图像框架。 | 指定图片模型与质量、RAW/Receipt/Ledger 绑定不变。 |
| Fast Scout 与最终帧审核 | `fast_frame_scout.py`、`frame_semantic_review.py` | **保留现有风险分流和 dHash/aHash**；可消费 OCR/人脸告警 | 让 critic 优先看疑似问题；避免重复引入感知哈希库。并发优化主要省墙上时间，不直接省 token。 | 画面是否兑现叙事、异常尺度与前后级差仍须实际像素语义审核。 |
| 字幕布局与图文审核 | `subtitle_layout.py`、`caption_image_audit.py` | **RapidOCR + ONNX Runtime**，属**文字检测 Tool**；字幕矩形相交为确定性算法 | 在未渲染字幕的底图检测招牌/屏幕等文字框，再与拟放置字幕区域比对；渲染后检查截断/缺字。清晰的几何问题可本地定位，减少重复视觉模型检查的候选成本。 | OCR 无文字不等于无遮挡；字幕与剧情是否相符、人话化和最终像素审核不由 OCR 放行。 |
| 发布与复盘 | `final_candidate_snapshot.py`、`post_publish_review.py` | 发布保持 SHA/清单校验；数据复盘先用现有确定性聚合 | 避免模型重复读完整发布资产与原始指标；规模扩大后再评估检索。 | 发布事实、冻结 Snapshot 和真实数据窗口不变。 |

## 4. 具体开源候选

| 候选 | 首选原因 | 实施前核对 |
| --- | --- | --- |
| [RapidOCR](https://rapidai.github.io/RapidOCRDocs/main/install_usage/rapidocr/install/) + [ONNX Runtime](https://onnxruntime.ai/docs/) | 可在本地 CPU 跑中文 OCR；适合先对 20 帧做离线图中文字检测。 | Windows 安装、模型首次加载、同一进程复用、每帧耗时、误检/漏检；记录确切模型版本与许可。 |
| [OpenCV YuNet](https://github.com/opencv/opencv_zoo/blob/main/models/face_detection_yunet/README.md) | 小型人脸检测，直接对应 baseline 找脸框。 | 多人、侧脸、远景、AI 生成脸的召回；分别核对 OpenCV 与模型文件许可。 |
| [OpenCV SFace](https://github.com/opencv/opencv_zoo/blob/main/models/face_recognition_sface/README.md) | 与 YuNet 同一工具链，可做角色母版的相似度预警。 | 先证明脸框稳定，再按本项目画风校准阈值；不得套用通用人脸验证阈值。 |
| [BAAI/bge-small-zh-v1.5](https://huggingface.co/BAAI/bge-small-zh-v1.5) | 中文故事检索的小型向量模型，模型卡标注 MIT。 | 当前不引入：故事指纹库仅 2 篇，账号学习索引 `sample_size=0`，不足以验证语义召回或摊平模型依赖成本。 |
| [SQLite FTS5](https://www.sqlite.org/fts5.html) | 纯词项检索可作为未来轻量基线。 | 当前不建索引：中文 tokenizer、短词与别名召回尚无语料评估；不能用于过滤正式 Recent-5 对比。仅作本地派生索引，不新建生产数据库权威。 |

不优先引入 YOLO/CLIP、FAISS、完整向量数据库、工作流框架或另一套本地语言模型。现阶段它们不能直接替代 Story OS 的核心语义审核，且会增加模型文件、依赖、运行时和许可维护面。是否升级取决于离线试点数据，而不是项目名气。

## 5. 建议落地顺序与验收

1. **基线**：用现有 `episode_performance.py` 和 `quota_observability.py` 记录每步骤调用数、输入 token（若能取得）、审核 Active/HOST_WAIT、返修次数。`quota_observability` 的日志计数是 best effort，不等于订阅额度。
2. **OCR 影子试点**：运行 `python episodes/_system/caption_ocr_diagnostic.py <episode_dir>`，在安装 `episodes/_system/requirements-ocr.txt` 后对历史底图和字幕位置做诊断，输出 `<episode>/meta/runtime/diagnostics/caption-ocr-shadow.json`。只写派生诊断，不改变审核结论。先看严重遮挡漏报、误报和本地耗时。
3. **人脸试点**：运行 `python episodes/_system/visual_face_diagnostic.py <episode_dir> --model <yunet.onnx>`，安装 `episodes/_system/requirements-face.txt` 并从 [OpenCV Zoo YuNet](https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet) 获取 ONNX 权重。报告写入 `<episode>/meta/runtime/diagnostics/visual-face-shadow.json`；工具只返回候选框，不分配角色、不生成身份裁切。对多人、侧脸、遮挡帧单独评估。
4. **连续性试点**：显式指定参考母版图与待比对图片，运行 `python episodes/_system/identity_sface_diagnostic.py <episode_dir> --reference <reference-image> --candidate <candidate-image> --yunet-model <yunet.onnx> --sface-model <sface.onnx>`。依赖同一份 OpenCV 可选依赖，并从 [OpenCV Zoo SFace](https://github.com/opencv/opencv_zoo/tree/main/models/face_recognition_sface) 获取 SFace 权重。报告写入 `<episode>/meta/runtime/diagnostics/identity-sface-shadow.json`，保存图像/模型 SHA、候选脸框及相似度排序；工具不认定角色身份、不设通用阈值、不写正式 frame review。先用多人物、侧脸、遮挡、不同光照样本校准后才能讨论自动分流。
5. **文本检索暂缓**：当前仓库 `reports/account-pattern-registry.json` 只有 2 篇故事指纹，`reports/account-learning-index.json` 的 `sample_size=0`。现阶段少量历史上下文直接读取更简单，向量模型/索引的依赖和维护成本大于预期收益。正式 Recent-5 审核必须覆盖所有现存最近 5 篇，任何本地检索都不能删减门禁比较集。待可检索的完整故事材料足以代表多种机制、并且通过离线召回评估后，再测 BGE；FTS5 需先验证中文词项召回。
6. **准入条件**：只有历史样本中的严重问题未被错误放过、总墙上时间与模型调用确有改善，才讨论减少某一类冗余预审。正式 FULL/PATCH Review、Evidence Gate 和状态推进保持原有权威，除非另立实施方案并回归。

本文件记录选型与阶段进度。RapidOCR、YuNet 和 Pillow 检查由 Story OS Python 模块直接调用；只有满足当前语义证据、OCR 完整和近乎纯色区域三项的字幕帧可由本地路径直接通过。现有 dHash/aHash 早已在正式逐帧审核中使用，无需重复接线。SFace 与文本检索尚无足够样本或语料支撑自动门禁，继续保持离线。未运行新 Episode，也不宣称已取得生产提速。
