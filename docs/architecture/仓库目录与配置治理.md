# Story OS 仓库目录与配置治理

## 目标结构

```text
storyOS/
├── config/                 # 人工配置与机器索引
│   ├── storyos.yaml        # 唯一人工配置入口
│   ├── index.yaml          # 最小读取集索引
│   └── profiles/           # 可复用机器 Profile
├── episodes/               # 剧集权威、证据与本地媒体
│   └── _system/            # 兼容保留的 canonical engine
├── standards/              # 创作规范、schema、template、registry
├── runtimes/               # Runtime/DAG 合同
├── reports/                # 账号、回归与升级报告
├── scripts/                # 仓库级运维入口
├── tests/                  # 新增测试优先进入此目录
└── .storyos/history/       # 安装、迁移和旧索引归档
```

## 边界

1. `config/storyos.yaml` 负责“当前怎么生产”。
2. `config/index.yaml` 负责“文件在哪里、当前阶段最少读什么”。
3. `standards/制作规范_正式版.md` 仍是唯一创作权威。
4. `<episode>/meta/episode-state.json` 仍是唯一阶段事实源。
5. Episode `meta/*.json` 是事实、证据或派生缓存，不因目录治理批量迁移。
6. `episodes/_system` 暂不迁往 `src/`；它是大量公开命令和历史证据绑定的 canonical 路径。若未来迁移，必须单独提供 wrapper、路径重写和全量回归。

## 读取协议

```text
config/storyos.yaml
→ config/index.yaml
→ START_HERE.md / SKILL.md / AGENTS.md
→ 当前阶段声明的最小读取集
→ 仅在缺依赖或冲突时扩大读取
```

这样既减少 token，也不把 YAML 变成第二状态机。
