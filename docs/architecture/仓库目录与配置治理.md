# Story OS 仓库目录与配置治理

## 目标结构

```text
storyOS/
├── config/                 # 人工配置与机器索引
│   ├── storyos.yaml        # 唯一人工配置入口
│   ├── index.yaml          # 最小读取集索引
│   └── profiles/           # 可复用机器 Profile
├── episodes/               # 剧集权威、证据与本地媒体
│   └── _system/            # 兼容保留的 canonical engine
├── standards/              # 创作规范、schema、template、registry
├── runtimes/               # Runtime/DAG 合同
├── reports/                # 账号、回归与升级报告
├── scripts/                # 仓库级运维入口
├── tests/                  # 新增测试优先进入此目录
└── .storyos/history/       # 安装、迁移和旧索引归档
```

## 边界

1. `config/storyos.yaml` 负责“当前怎么生产”。
2. `config/index.yaml` 负责“文件在哪里、当前阶段最少读什么”。
3. `standards/制作规范_正式版.md` 仍是唯一创作权威。
4. **当前兼容期** `<episode>/meta/episode-state.json` 仍是阶段事实源；目标架构按 `Story_OS_数据持久化分层与JSON瘦身改造方案_V1.0.md` 逐步迁到 MySQL `TB_EPISODE_STATE`。切换必须经过双写、对账、影子读与回滚演练，禁止出现 JSON/MySQL 双主。
5. Episode `meta/*.json` 不再被视为天然长期持久化格式：长期事实迁 MySQL，可重建热状态迁 Redis，派生视图改为 API/CLI 按需导出；迁移完成前保留兼容读写。
6. 新增 Episode JSON 必须先通过存储归属判断，无法说明“为什么不能进 MySQL/Redis/按需导出”的，不应新增为长期文件。
7. `episodes/_system` 暂不迁往 `src/`；它是大量公开命令和历史证据绑定的 canonical 路径。若未来迁移，必须单独提供 wrapper、路径重写和全量回归。

## 读取协议

```text
config/storyos.yaml
→ config/index.yaml
→ START_HERE.md / SKILL.md / AGENTS.md
→ 当前阶段声明的最小读取集
→ 仅在缺依赖或冲突时扩大读取
```

这样既减少 token，也不把 YAML 变成第二状态机。
