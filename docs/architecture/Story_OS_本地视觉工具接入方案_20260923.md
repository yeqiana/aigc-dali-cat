# Story OS 本地视觉工具接入方案

状态：本地字幕位置直过已按用户确认的风险取舍接入；两篇既有 Episode 的离线回放发生在放宽规则之前，尚无新规则的净提速数据。日期：2026-09-23。适用范围：RapidOCR、OpenCV YuNet、OpenCV SFace 的生产链路接入。

## 当前实际落地（2026-09-23）

- `runtime.review.local_vision_shadow.enabled=true` 默认运行 RapidOCR / YuNet 诊断；`gate_hint=true` 将阳性提示注入仍需运行的 Critic，帮助复核疑似遮挡或缺脸。
- `local_gate_enabled=true` 默认启用**本地字幕位置直过**：当前逐帧语义审核必须已通过且绑定当前字幕，OCR 必须完整且未发现原图文字重叠，规范布局和发布图渲染完整性必须通过。满足条件的帧直接记录本地通过，不启动该帧视觉 Critic；证据缺失或异常则回退视觉 Critic。此取舍由用户明确确认，接受漏检字幕盖住人物、手部动作、道具或线索的风险。关闭开关即恢复原有全量审核路径。
- 本地通过记录底图、字幕及布局 SHA 和语义审核来源；这些证据漂移后不能复用。YuNet 仍只提供候选人脸框，不替代 Visual Lock 的九项视觉审核；SFace 仍为离线工具。
- Pillow `ImageChops.difference` 已接入发布前字幕像素完整性检查：对比底图和发布图，只允许规范字幕区域变化。明确的画布变化、未渲染字幕或区域外像素变化在发起视觉 Critic 前报错；来源 SHA 不一致或颜色模式无法确认时返回 `UNKNOWN`，交由现有校验与视觉审核处理。这是技术质量检查，不判断画面语义。
- 此路径旨在减少重复像素调用。当前尚无放宽规则后的真实 Episode 分流数量、模型调用节省或整体耗时数据；不能据此声称已取得生产提速。

## 1. 结论与现状

RapidOCR 和 YuNet 已接入诊断；字幕审核按上述条件直接本地放行，其他帧保留 Codex Vision 审核。FULL/PATCH Review、Evidence Gate 和 Episode 状态推进保持原逻辑。SFace 继续离线验证。

当前 `config/storyos.yaml` 指定整体 Runtime 优先 `CODEX`，独立像素审核使用 Codex Vision critic。三种开源模型均是 Story OS Python 内部的**本地算法 Tool**，不是新的 Runtime、Agent、Skill 或 MCP 服务；Python 业务模块决定何时调用，诊断文件属于可重建的派生数据。不得把分数或检测框写成正式审核 PASS/FAIL。

已有离线数据只支持“可低成本试接”，不支持“已提速”：

| 工具 | 现有样本结果 | 证据缺口 |
| --- | --- | --- |
| RapidOCR | 《东海龙宫》20 帧，14.658 秒，20 帧完成、0 个遮挡候选 | 样本没有已确认的字幕遮字正例，不能测漏报；按当前用户确认的风险取舍，须与语义、布局和渲染证据合用才允许跳过审核。 |
| YuNet | 《玻璃另一边的手》Visual Lock baseline 检出 2 张脸，约 0.124 秒 | 仅双人正脸一帧；侧脸、遮挡、远景及更多人尚未覆盖。 |
| SFace | 20 张候选中 16 张检出脸；母版检出 2 张脸 | 母版混入第二人，同源帧排名最高；跨帧身份漂移排序没有可信标注。 |

上面的耗时是工具本身的离线耗时，与图片生成或模型审核耗时不是同一口径。本地链路本身增加耗时；字幕直过可能减少视觉审核调用，净收益须按实际分流帧数测量。

## 2. 接入位置与数据流

```text
Visual Lock baseline 生成完成
  → visual_lock_baseline_gate.py 准备审核
  → YuNet 检测候选脸框 → 派生诊断
  → 原有独立像素 Critic → 原有批准/裁切/门禁

底图 + 当前字幕布局
  → subtitle_layout.py 生成 canonical layout 报告
  → RapidOCR 读底图、按字幕矩形计算疑似重叠 → 派生诊断
  → caption_image_audit.py 继续审核最终带字幕像素
  → 原有修复、复审和门禁

单人角色母版 + 跨帧候选（后续阶段）
  → SFace 只给疑似漂移排序 → 派生诊断
  → identity_continuity.py / 逐帧像素审核仍作正式判断
```

### RapidOCR：字幕图文审核前的提示

- 输入必须来自 `subtitle_layout.py` 的 canonical `meta/subtitle-layout-audit.json`：底图路径及 SHA、字幕矩形、字幕源 SHA、layout 报告 SHA。只在这些输入当前有效时使用诊断；漂移则重算或标记 `STALE`，不可复用旧结果。
- 业务接线点建议放在 `caption_image_audit.ensure()` 已完成布局核对、筛出 dirty frames 之后、`_run_chunk()` 发起正式像素审核之前。按 dirty frames 运行，避免对未变化帧反复 OCR。报告仍存 `meta/runtime/diagnostics/caption-ocr-shadow.json`，以当前图片、布局、工具版本绑定。
- OCR 只输出重叠候选与检测状态；单独的 `NO_CANDIDATE` 不是“字幕无遮挡”。当前策略要求语义审核、OCR、布局和渲染完整性证据同时有效后直接跳过该帧模型审核；它会漏掉非文字遮挡，属于用户明确接受的风险。OCR 不直接改字幕 y 坐标或变更现有自动修复次数。
- 首阶段不要把 OCR 文本注入审核 prompt：先核对误报、漏报和成本。后续若证实有用，只向审核展示当前帧的少量候选坐标及来源 SHA，并要求 Critic 独立看最终像素；正式判断不引用 OCR 结论代替像素证据。

### YuNet：Visual Lock baseline 的候选人脸框

- 输入取 `visual_lock_baseline_gate.generated_baseline()` 对应的实际图片及 SHA、Frame Contract SHA。建议在 `prepare_review()` 生成 DRAFT 后触发；不要改变其 `face_boxes`、`checks`、`decision` 和已有 schema。工具缺失、超时或图片漂移时仅写 `UNKNOWN`/错误摘要，原审核照常运行。
- 诊断报告 `meta/runtime/diagnostics/visual-face-shadow.json` 保存人脸矩形、置信度、图片/模型 SHA、耗时。候选框不自动分配 P01/P02，不自动生成裁切或锁角色母版；正式 `face_boxes` 仍由现有审核确认。
- baseline 之外的多人、侧脸、远景样本通过离线命令补齐后，再讨论是否扩到其他 Visual Lock 帧；不在第一阶段对全部 Batch 帧增加同步识别。

### SFace：暂不接入常驻流程

- 保留 `identity_sface_diagnostic.py` 显式离线入口。先换成已核实**单人**角色母版，收集同角色不同帧、不同角色、侧脸、遮挡、远景与明显漂移的人工标注样本；未检出脸要保留 `UNKNOWN`，不可按低相似度处理。
- 比较排序能否把人工确认的明显漂移帧排到前部，同时记录误报和漏报；不套用通用人脸阈值，不给自动 PASS/FAIL。完成离线准入后另行评估在逐帧审核前提供优先排查列表，仍不修改 `identity_continuity.py` 的权威证据。

## 3. 接口、失败回退与存储边界

1. **封装**：复用现有诊断脚本的识别逻辑，提供窄的 Python 内部调用接口；CLI 保留作为离线复现入口。已增加 `enabled`、`gate_hint` 和 `local_gate_enabled` 配置；未增加 MCP、后台进程、数据库表或生产 API。依赖仍为可选，模型权重放在本地 `.storyos_cache/`，不入 Git。
2. **派生证据**：每条结果包含工具及模型版本、图片 SHA、相关布局/合同 SHA、开始与结束时间、耗时、状态和错误类型；文件采用原子写入，避免中断留下“完成”的残缺报告。诊断文件不承担门禁和阶段事实源。
3. **fail-soft**：导入失败、模型缺失、超时、OCR/检测异常、无脸、损坏或不匹配的缓存，都返回 `UNKNOWN`，记录可排查错误并继续原审核。不要把异常当成“无问题”；不要因此改变已存在的审核失败语义。
4. **成本上界**：只处理本次已变更的底图/布局或 baseline；避免每次 Resume 都加载模型、重扫 20 帧。是否复用进程内模型实例，应以实测启动和驻留成本决定，不能引入跨帧 Codex 会话复用。诊断失败不得触发重新生图。
5. **安全边界**：诊断输出仅保存项目相对路径和 SHA，不复制原图、不写 API Key、Authorization Header 或外部服务凭据。SFace 特征向量首期不落盘，只保存排序分数及来源绑定。

## 4. 分阶段实施与验收

| 阶段 | 修改范围 | 必须验收 | 推进条件 |
| --- | --- | --- | --- |
| A：影子接线 | OCR 接 `caption_image_audit.py`；YuNet 接 `visual_lock_baseline_gate.py`；内部 Tool 封装和派生报告 | 离线单元/系统回归验证输入 SHA 漂移、缺依赖、损坏报告、异常/中断回退；原 FULL/PATCH、字幕审核、baseline 批准及阶段门禁结果不变 | 诊断可见、故障不阻断、无额外模型调用。 |
| B：样本评估 | 不改生产门禁；补已知遮字正例与无字负例，补多人/侧脸/远景/遮挡人脸样本 | 逐帧记录人工标注、误报、漏报、未检测、单张 p50/p95 和新增墙上时间；对真实 Episode 对照审核调用数/token（仅在可观测时） | 严重遮挡无漏报，复杂脸型覆盖足够，再决定提示是否进入 critic 上下文。 |
| C：SFace 离线准入 | 清洁单人母版和已标注跨帧集 | 排序与人工标注对照；同源帧不得当跨帧证据；无脸单列 `UNKNOWN` | 只有排序稳定且误漏报可接受，才另立生产提示接线变更。 |
| D：收益决策 | 仅在 B/C 有数据后另提方案 | 同集、同版本、同审核口径对比总墙上时间、模型调用、可取得的 token 和返修质量 | 没有质量回退且净收益明确，才讨论减少某类冗余预审；正式审核/门禁变更需要单独评审。 |

首阶段本地回归不启动新 Episode，也不调用图片或审核模型；利用注入式假 Tool/固定图片检查调用位置与 fail-soft。实际省 token 和端到端提速需要后续真实跑批验收，不能以离线工具耗时推断。
