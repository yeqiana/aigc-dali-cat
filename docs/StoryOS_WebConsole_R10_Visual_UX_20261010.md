# StoryOS Web Console R10：视觉规范与布局改造验收（2026-10-10）

## 目标
- 保留 StoryOS 当前 React/TypeScript 工作台和本机真实作品状态 API，减少生硬边框、杂乱信息、状态误导和页面重叠。不是纯换色，而是统一导航/信息层次/数据源提示/筛选交互。
- 所有现有 API 与入口保持；不触发 MySQL、Redis、图片模型、正式 Runtime 任务或阶段写入。

## 四槽隔离提交与范围
- 槽 1 设计系统：`2318dde5`，主题语义色、卡片/状态/按钮/焦点规范、240px 侧栏、60px Header、明确选中态。
- 槽 2 工作台：`e6709487`，工作区标题区、4 个摘要卡片、真实文件状态和历史作品分区、搜索及关注卡。
- 槽 3 监控：`19c95d31`，统一状态颜色、强化来源区分、监控工具栏支持换行、列表证据可见性与布局。
- 槽 4 工作流：`3962d705`，7 阶段序列图、可扫描的作品状态行、按需打开的只读详情卡片。
- 审图整改：常驻的本机真实文件提示由底部遮挡性横幅移入全局顶栏；保留 `data-testid=local-real-evidence-banner` 和明示的非权威状态。工作流七个节点改为中性序号/点，避免误示所有阶段已完成。

## 核心视觉约束
- 深色基底 `#0b1019`，导航 `#101724`，内容表面 `#151e2c`；保留浅色及渐变浅色模式。颜色写入主题 token，不分散重复写业务颜色。
- 页面级标题 22–28px，区块标题 15px，信息层级 / 11px eyebrow；表格正文不低于可读范围。主按钮蓝色只用于新建等明确动作。
- 标准卡片采用 12–14px 圆角、弱边框和克制阴影；hover/focus 提示保留，键盘 focus-visible 描边不取消。
- 真实磁盘状态的字段、人数、运行状态按既有 API 合同展示，未知心跳保持未知；严禁视觉上混成实时调度。
- 工作流节点展示结构顺序，不使用已完成的勾选标志，不在前端给出阶段跳过操作。

## 浏览器验收
- 先以 Node + Python 本机真实文件 API 启动，只监听 127.0.0.1:3102（本轮隔离 UI）和 127.0.0.1:19117（既有只读后端）；不会与 3100 主分支 UI 争用。
- `npm run lint`、`npm run build -- --base=./`。
- `npm run test:visual-ux` 检查首页/监控/工作流和 1366px 首页真实浏览器标题、数据来源、操作控件名称、水平溢出；输出到 Git 忽略目录 `.storyos-tmp/ui-qa/r10/`。
- `npm run test:local-real` 检查真实数据 API 来源、20 条状态、未知心跳、首页和监控导航。
- 旧回归覆盖 Bundle 分包、Episode/Run 数据内容一致性、监控分页锁、Workflow、离线五页面及可访问性。

## 运行及边界
- 目标分支合并后可从 `web-console` 执行 `npm run dev:local:real`，访问 `http://127.0.0.1:3100/`。
- 主工作区未跟踪的业务文件必须保留，合并采用安全同步+快进；主分支已合入的其他提交不能被覆盖。
- 本轮不等于正式 MySQL/Redis 权威 Runtime 联调通过：读端仍是 `local_workspace_episode_state_file` 的真实磁盘状态。
