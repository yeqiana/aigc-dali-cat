# StoryOS R17 控制台三轮四槽并发改造与浏览器验收

日期：2026-10-11

## 目标

用户反馈整体 Console 审美、布局与信息组织不合理，要求至少三轮、每轮 4 个并发槽位。此次重构遵循根目录 `DESIGN.md`：**高密度控制台、读端真实数据、表格优先、弱卡片/弱装饰、语义状态色、桌面响应式**。不覆盖已有素材和其他任务的本地修改，不触发图像生成、支付或生产写入。

## 数据真实性与保护

- `3100` 日常 UI 与 `19117` 本机只读 API 提供的是 `episode-state.json` 和已批准图片目录数据。
- 首页、监控与工作流明确“本机文件 · 只读”，**不暗示 Worker 在线、实时队列、运行健康/并发能力**。
- 作品库及工作台沿用 R16 批准图，只把 `media/approved` 素材作为可视资产；不改审核判定，不晋级 candidates。
- 未实现生产写入、生成/发布/审核操作，不修改 `episodes/` 文件。
- 原始修改与未跟踪素材须在最终合并前后核对；仅允许快进合并，不允许强制覆盖。

## 自动化与视觉验收项目

- R1 / R2 / R3：每个槽位单独 `npm run lint` + `npm run build -- --base=./`，共 12 组验证。
- 全部集成后重新执行 `lint` / `build` / `test:bundles` 及 API、monitor、workflow、console、episodes、runs、readonly-probe、accessibility 九组核心回归。
- `3111` 隔离预览代理真实的 `19117` 数据；R10（工作台、监控、工作流、1366px）、R11（作品库、Agents、审计日志、设置）、R12（故事制作、历史 Run）、R13（实际分页 + 主题）、R16（批准媒体，含无批准图反例）持续验收。
- 新增 `npm run test:responsive`：1024px 首页/监控 + 1280px 作品库/工作流，真实 Chrome **4/4**，检查数据主区可见、只读来源和无整页水平溢出。
- 自动化的标题与按钮定位调整为新版可访问性名称（例如“审计日志”“标准七阶段”“打开故事 {title}”），没有删除实际的数据验证。
- 截图存于 Git 忽略的 `.storyos-tmp/ui-qa/r10-r16`，不提交真实用户图片。

## 后续真实缺口

R17 主要整治现有控制台的**信息层级与布局**，不是宣称 UX 已经达到最终设计稿。对历史 Run 与某帧具体图片的权威归因、在窄屏下将主侧栏折叠为 64px、日志页 100+ 记录的表格虚拟化等仍需独立需求和证据，不应伪造完成状态。
