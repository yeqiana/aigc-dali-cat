# StoryOS 瘦身性能基线采样协议（2026-10-10）

## 只读入口

`python scripts/storyos_perf_evidence_snapshot.py <episode_dir> --json`

该工具**只读本地现存** `meta/provider-receipts/model-executions/*.json` 与 `meta/runtime/trace-events.jsonl`，不会调用模型、数据库、Provider 或改写 Evidence。仅能代表采集到的事实，不是完整生产结果。

## 可度量指标与限制

| 指标 | 本地证据 | 未满足时 |
| --- | --- | --- |
| model 调用数 / 角色 / 状态 | 每调用独立 receipt | 报告 0 个本地回执，不断言真实调用数为零 |
| 模型单调用 P50/P95 / 耗时之和 | receipt.duration_ms | `null`；总和可能包含重叠，不能当 Episode 墙钟 |
| Token 消耗 | receipt.usage / receipt.tokens，覆盖数另外报告 | `null` 或注明仅局部覆盖 |
| Trace Span P50/P95 | local trace JSONL（若存在） | `null`，MySQL Authority 模式不可用时不回退伪造 |
| 完整 Episode 墙钟 / 自动恢复成功率 / 图像质量 | 需要独立的权威端到端对照 | 明确 `null` |

不要用录入前后代码行数、单测通过数推断生产速度。至少应选同规格 Episode，记录合同 SHA、脚本版本、模型配置与图片预算；双作品场景保持全局 5 图令牌和单 Episode 唯一 Owner。比较时先排除素材内容、模型供应商和网络波动，再观察任务排队、模型推理、I/O、Review 返修各环节耗时。不得对锁定历史 Episode 重新付费出图以“测性能”。
