# 0. 术语冻结（本方案统一口径）

为避免再次把“网页端”“WORK”“DevSpace”“WEB Runtime”混为一谈，本方案先固定术语：

```text
ChatGPT 网页 / App
= 用户界面（UI）
≠ WEB Runtime

WORK
= 当前 ChatGPT 主控 Product Runtime / 主控 Agent
= 负责理解、推理、创作、文本/逻辑判断、编排和最终 Authority

DevSpace
= WORK 访问本地 Windows 工作区的工具 / Transport / Execution Surface
= 文件、Git、测试、命令、代码修改能力
≠ 独立 AI 模型
≠ Review Provider

CODEX_IMAGE
= 独立图片生成 / 图片返修执行 lane

CODEX_VISION_REVIEW
= 独立、fresh、ephemeral 的真实像素视觉审核 lane

WEB Runtime
= Story OS 历史运行时类型 / 旧 WebCodex 兼容概念
≠ “用户正在 ChatGPT 网页端使用 Story OS”
```

因此，用户在 ChatGPT 网页端说：

```text
@DevSpace 看 Story Lock / 改代码 / 跑测试 / 评审 JSON
```

其真实关系是：

```text
ChatGPT UI
↓
WORK 主控 Runtime
↓
DevSpace 工具
↓
本地 storyOS 工作区
```

这仍然是 `WORK`，不是 `WEB Runtime`。

同时必须承认一个执行边界：

> **DevSpace 可以让当前 WORK 会话读写本地文件，但本地 Python 进程不能凭空“启动一个 WORK 模型”。**

因此新架构不得再通过 `devspace agents run claude/opencode/pi` 来伪装 WORK。需要 WORK 参与的文本/治理 Host Action，应由当前 ChatGPT WORK 主控在一次全自动任务生命周期内直接通过 DevSpace 消费；需要完全本地无人值守的像素审核，则走 `CODEX_VISION_REVIEW`。

# 1. 背景与结论

当前 Story OS 已经完成了大量 WORK-first、Runtime DAG、Codex 图片执行、Host Loop、PREIMAGE 并发等治理，但 2026-09-13 在《天界普通女生的一天》真实全自动生产中暴露出一个更基础的职责划分问题：

> **系统把“Review Authority（审核权）”与“Vision Capability（识图能力）”混为一谈。**

现有配置倾向于：

```text
Review = WORK + DevSpace
Image = CODEX
```

这在文本审核上成立，但在实际像素审核上不成立。

Frame01 已经由 Codex 自动生成成功，但随后：

```text
REVIEW_ORDINARY_BASELINE
executor = WORK
```

系统为了维持 WORK-only Review，进一步尝试通过 DevSpace 的 Claude / OpenCode / Pi Provider 做 actual-pixel review，最终：

```text
Claude   -> PROVIDER_UNAVAILABLE
OpenCode -> PROVIDER_UNAVAILABLE
Pi       -> AGENT_INTERNAL_ERROR
```

而仓库历史实现与现存代码已经证明：

- Codex 具备真实图片输入能力；
- Story OS 曾经直接使用 `codex exec --ephemeral -i <image>` 做 Visual Critic；
- `visual_lock_baseline_gate.py`、`visual_lock_v21.py`、`frame_semantic_review.py`、`caption_image_audit.py`、`rolling_frame_review.py` 等模块仍保留 Codex actual-pixel review 路径；
- 历史 Episode 中存在真实 `CODEX_ISOLATED` / `local_codex_cli` critic provenance。

因此本次修复方向不是继续修 Claude / OpenCode / Pi，而是重新建立清晰职责边界：

```text
ChatGPT UI            = 用户交互界面，不参与 Runtime 判定
WORK                  = 当前 ChatGPT 主控 Product Runtime / 主控 Agent
DevSpace              = WORK 的本地工作区工具，不是模型 Provider
CODEX_IMAGE           = 图片生成 / 图片 Repair
CODEX_VISION_REVIEW   = 独立、只读、actual-pixel 视觉审核
WEB Runtime           = 历史兼容读取，不再参与新生产路由
```

这里最重要的修正是：

```text
WORK + DevSpace
```

本身就足以完成 Story、PREIMAGE、代码/配置/JSON 审核、文本语义 Review、治理判断和本地仓库操作；不需要再引入 Claude / OpenCode / Pi 才能“让 WORK 看本地文件”。

本方案目标：

> **恢复 Codex 的视觉 Critic 职责，同时保持 WORK 对 Story / PREIMAGE / Governance / Release Authority 的控制，不重新退回“Codex 全流程接管”。**

# 4. 目标 Runtime 职责模型

## 4.1 WORK

WORK 定义：**当前 ChatGPT 主控 Product Runtime / 主控 Agent。**

它可以运行在 ChatGPT 网页端、App 或其他产品 UI 上；UI 形态不改变它仍然是 WORK。

职责：

- 用户意图理解
- Story 创作
- Concept Ambition
- Recent5 语义判断
- Story Semantic Review
- Character / World / Environment Authority
- PREIMAGE Authority Merge
- 读取并审核本地 `.md/.json/.yaml/.py` 等文本/结构化证据
- 代码/配置/契约分析
- Runtime DAG 编排
- Repair 决策
- Release Governance
- canonical stage transition
- 最终 PUBLISH_READY Authority

WORK 通过 DevSpace 可以直接完成：

```text
读本地 Story / Storyboard / Gate / Contract
↓
分析
↓
写 candidate / 修改配置 / 执行 verifier
↓
形成正式文本/治理 evidence
```

这类任务不需要 Claude / OpenCode / Pi Provider。

WORK 不负责：

- 图片生成；
- 图片返修；
- 在没有真实像素输入能力时声称完成 actual-pixel 识图。

如果当前 WORK 产品会话本身未来获得可靠的图片附件读取能力，可以作为另一种 Vision Provider，但必须经过 capability check 和独立 provenance；本方案默认仍使用 `CODEX_VISION_REVIEW` 保证本地全自动和可重复性。

---

## 4.2 DevSpace

DevSpace 定位：**WORK 的 Workspace Transport / Execution Surface，不是独立审核模型。**

职责：

- 文件读取 / 写入
- Git inspection
- 测试 / build
- 工作区命令
- 本地代码修改
- WORK 对 `D:\workspace\...\storyOS` 的访问通道

正确关系：

```text
WORK decides / reasons
↓
DevSpace reads or changes local workspace
↓
WORK verifies / decides next action
```

DevSpace 不负责：

- 自己“思考”并成为 Review Authority；
- 作为实际视觉 Critic；
- 强制依赖 Claude / OpenCode / Pi 做生产主链审核；
- 把 `devspace agents run <provider>` 当成 WORK 的定义。

因此：

`bounded_devspace_provider` 不应作为生产主链 mandatory dependency，建议从正式主架构中废弃；如保留，仅作为实验性外部 Provider 扩展，不参与 Golden Path。

---

## 4.3 CODEX_IMAGE

职责：

- Image Generation
- Image Repair / Edit
- 图片 worker
- raw candidate generation

特点：

- max inflight = 3
- isolated worker CODEX_HOME
- 只产生图片和 execution receipt
- 不做最终审核
- 不推进 canonical stage

---

## 4.4 CODEX_VISION_REVIEW

新正式职责 lane。

职责：

- Visual Lock baseline actual-pixel review
- Visual Lock four-admission critic
- Fast Scout
- Rolling Review
- Production Batch Review
- Final Frame Semantic Review
- Incremental Frame Review
- Caption ↔ Image Audit
- Subtitle Obstruction actual-pixel review
- Release Visual Evidence

执行要求：

```text
fresh session
--ephemeral
image attachments only as required
frozen Review Contract
immutable source SHA
candidate JSON only
```

必须和 CODEX_IMAGE 隔离：

```text
CODEX_IMAGE worker A
→ generate image
→ session closed

CODEX_VISION_REVIEW critic B
→ fresh ephemeral session
→ read frozen image + contract
→ PASS / FAIL
```

禁止：

- 同一个生成 session 自审；
- Vision Critic 修改图片；
- Vision Critic 修改 Story / Storyboard / Gate Authority；
- Vision Critic 直接 transition `episode-state.json`。

# 5. 配置重构方案

当前：

```yaml
runtime:
  review:
    runtime: WORK
    workspace_transport: DEVSPACE
    isolated_critic_required: true
    fresh_product_review_turn_required: true
    allow_webcodex: false
    allow_local_codex_review: false
```

问题：粒度过粗。

建议改为：

```yaml
runtime:
  preferred_runtime: WORK
  image_execution_runtime: CODEX

  review:
    text:
      runtime: WORK
      workspace_transport: DEVSPACE
      host_execution: CURRENT_WORK_SESSION
      # isolated/fresh turn 是 review quality policy，不通过 DevSpace subagent provider 模拟
      fresh_turn_preferred: true

    vision:
      runtime: CODEX
      isolated_required: true
      ephemeral: true
      generation_session_reuse: false
      controller_model: null
      reasoning_effort_default: medium
      reasoning_effort_fast: low
      reasoning_effort_final: high

    governance:
      runtime: WORK
      workspace_transport: DEVSPACE

    allow_web_runtime: false
```

兼容迁移：

- `runtime.review.runtime` 暂时读取为 legacy alias；
- `allow_local_codex_review=false` 改为只约束 text/governance review，不能继续阻断 Codex Vision；
- 新增 `runtime.review.vision.runtime=CODEX`；
- `bounded_devspace_provider` 标记 deprecated，不再作为 Golden Path fallback；
- 不允许通过 `claude/opencode/pi` DevSpace subagent 来“模拟 WORK”；
- 如需记录用户界面，可新增 `ui_surface=CHATGPT_WEB|APP|OTHER`，但不得影响 runtime router。

## 6.3 episode_runner.py / workflow_runner.py

统一本地 host action 类型：

```text
CODEX_IMAGE       # 本地进程可直接执行
CODEX_VISION      # 本地进程可直接执行
WORK              # 当前 ChatGPT 主控 Host Action
HUMAN             # 真正需要用户直接决策
```

增加：

```text
local_vision_action()
run_local_vision_action()
```

continuous local loop 能执行：

```text
CODEX_IMAGE
→ CODEX_VISION
→ CODEX_IMAGE
→ CODEX_VISION
```

而 WORK action 的正确语义是：

```text
Runtime 生成 frozen Host Action Contract
↓
当前 ChatGPT WORK 主控通过 DevSpace读取/处理本地证据
↓
WORK 写 candidate / evidence
↓
正式 finalizer / verifier
↓
Runtime 继续
```

不要让本地 Python 通过 `devspace agents run claude/opencode/pi` 去“代替 WORK”。

### 6.3.1 两种运行形态必须区分

**A. ChatGPT + DevSpace 主控模式（本项目当前 Golden Path）**

```text
用户一句话
↓
当前 ChatGPT WORK 会话持续编排
↓
DevSpace 执行本地操作
↓
Codex Image / Vision 由本地 lane 自动执行
↓
WORK Host Action 由当前 ChatGPT 主控直接消费
```

这可以实现用户体验上的“一句话后不再输入继续”。

**B. 纯本地 CLI 无 ChatGPT Host 模式**

```text
python story_os.py run --full-auto
```

本地进程可以无人值守完成 deterministic、CODEX_IMAGE、CODEX_VISION 步骤，但不能凭空创建 ChatGPT WORK。遇到必须由 WORK 完成的 Story / Text Review / Governance action，应明确返回 `WORK_HOST_REQUIRED`，不能用其他 DevSpace Provider 冒充。

因此“full-auto”必须区分：

```text
hosted_full_auto = ChatGPT WORK 主控下真正全流程
local_full_auto  = 本地可执行 lane 全自动，WORK action fail-closed / handoff
```

这不是退化，而是对真实能力边界的诚实建模。

# 8. Provenance 设计

建议正式区分：

```text
WORK
WORK_ISOLATED          # 仅当产品层真的存在 fresh isolated WORK turn
CODEX_VISION_ISOLATED
CODEX_IMAGE
```

`WORK_DEVSPACE_BOUNDED` 只作为本次迁移期历史兼容 provenance 保留，不再作为目标主链类型。原因是 DevSpace 本身只是 WORK 的工具，不应通过一个特殊 runtime 名称暗示“DevSpace 是另一个 reviewer”。

## CODEX_VISION_ISOLATED 必须包含

```json
{
  "runtime": "CODEX_VISION_ISOLATED",
  "base_runtime": "CODEX",
  "isolated_session": true,
  "execution_source": "local_codex_cli",
  "session_reused_from_generation": false,
  "review_scope": "...",
  "attempt": 1,
  "log": "...",
  "reviewed_at": "..."
}
```

兼容历史：

现有：

```text
CODEX_ISOLATED
```

继续可读。

新 evidence 建议统一写：

```text
CODEX_VISION_ISOLATED
```

如果改 provenance schema 风险过大，也可第一阶段继续写 `CODEX_ISOLATED`，增加：

```text
review_capability = vision
```

但长期建议显式区分。
