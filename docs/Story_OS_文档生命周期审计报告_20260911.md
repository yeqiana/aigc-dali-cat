## 一、审计目标

对当前 Story OS 仓库中的 docs、reports、architecture 等文档资产进行生命周期审计。

目标：

- 识别重复、过时、阶段性文档
- 区分权威文档、历史证据、实验文档
- 为后续归档/合并提供依据
- 不直接删除、不直接迁移生产相关文档

# 三、文档分类原则

## 1. 权威文档（保留）

定义：

当前生产规则、架构设计、运行契约来源。

处理：

- 保留原位置
- 不随意归档

示例：

- standards
- architecture 中当前有效设计
- Runtime 契约文档

---

## 2. 验收证据（保留，建议分类）

定义：

证明某阶段完成的不可变证据。

处理：

保留内容，不删除。

后续建议进入：

```
reports/acceptance/
```

---

## 3. 历史演进文档（归档候选）

定义：

已经被后续版本覆盖的方案。

例如：

- V1 规划文档
- 早期迁移方案
- 阶段性设计

处理：

进入 archive。

---

## 4. 实验分析文档（研究区）

定义：

选题、竞品、方向探索。

建议：

```
reports/research/
```

---
