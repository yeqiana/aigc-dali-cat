# StoryOS 00-06 原生 Codex 模型兼容与续产准入（2026-10-10）

## 结论与作用域

本文件只针对本机正式 Episode `episodes/00_独立篇/06_五十亩山地之后`（MySQL 权威标识 `00-06`），不复用历史 `00-05` 的 Attempt、Revision、Review 或发布证据。GitHub checkout 未必包含本地 ignored Episode 和 `.storyos/runtime-launcher/runtime.env`，因此 GitHub CI 不能宣称已验收本地 MySQL 或正在出图。

已观察到的原生 CLI `0.153.4` 低于 `gpt-6-luna` 官方目录指定的最低客户端版本 `0.155.0`。最低版本符合要求 **不代表** ChatGPT 登录态有模型权限；必须单独做真实、最小化原生模型请求。禁止以 `codex login status`、CLI `--help`、版本通过或桥接认证存在性代替执行成功。

模型契约不是普通文本配置：已冻结 Episode 的模型权威在 MySQL `MODEL_POLICY` Contract；本机 `config.toml` 默认模型不会覆盖 StoryOS 调用中的显式 `-m`。不得无审计地修改冻结 SHA、删除快照、重建 Episode、篡改 Review Authority、清空 UNKNOWN Attempt 或拿 `image_payload` 的 fallback 充当文本模型回退。

## 四槽位滚动执行

| 槽位 | 边界 | 验收产物 |
| --- | --- | --- |
| 1：本机 Codex 兼容 | 找到 `Get-Command codex -All` 的实际可执行文件与安装来源，更新到 `0.155.0` 或更新，检查 User Runner 的实际二进制并以 ChatGPT 登录态做最小 Luna 实测；不能走 OpenCodex/WebCodex | 版本、路径来源（不公开用户名）、原生成功/权限拒绝的明确分类 |
| 2：模型契约 | 对比 `config/storyos.yaml`、Episode MySQL `MODEL_POLICY`、Runner 显式 `-m`、有效 Policy SHA，按正式 Authority 检查 | 当前/冻结模型、SHA 与权限一致性、可审计裁决 |
| 3：隔离修复和测试 | 在独立工作树/PR 分支修复；`plan` 增加只读 CLI 最低版本阻断；验证没有回落到代理 | 单元及系统测试通过，PR 与中文提交 |
| 4：00-06 生产续跑 | 在 1–3 验收后核对本地 MySQL 阶段、Driver、Review/Attempt 与冻结输入，原生 Canonical DAG 续跑至 `PUBLISH_READY` | 按 Authority 出具故事、25 帧图、真实审核、字幕和发布资产；不进行视频制作 |

## 本机 PowerShell 顺序

```powershell
cd D:/workspace/YeQianWorkSpace/yeqian/storyOS
Get-Command codex -All | Select-Object Source
codex --version
codex login status
npm ls -g @openai/codex --depth=0
```

如确认是 npm 安装，再通过受控升级：

```powershell
npm install -g @openai/codex@latest
codex --version
```

先做 **不消耗模型调用** 的准入检查：

```powershell
python scripts/storyos_codex_cli_readiness.py --bridge
python scripts/storyos_codex_managed.py plan "episodes/00_独立篇/06_五十亩山地之后"
```

`plan` 现在额外检查原生文本/审核/图片控制器模型的最低 CLI 版本。该检查通过仍明确标注 `model_entitlement_verified=false` 与 `tool_generation_proven=false`，不能据此声称出图能力或账户权限已验证。历史 `IDEA_LOCKED` 的状态只能由本地 MySQL 重新查询确认。

CLI 升级及真实 Runner 路径验证后，在授权的小规模原生调用中测试 Luna（**这一步确实触发一次模型请求**）：

```powershell
codex exec --ephemeral --skip-git-repo-check -m gpt-6-luna -c 'model_reasoning_effort="high"' -s read-only "只输出 CODEX_LUNA_OK"
```

成功后还必须确认：真实执行身份与生产 Runner 一致、冻结模型绑定一致、所有图片 Attempt 终态可信、MySQL 权威允许续跑、真实图片工具能力在正式流程中被验证。若服务端仍报不支持 ChatGPT 登录态，停止，不得用 API key、OpenCodex、WebCodex 或未授权降级模型伪装成功。

仅在符合上述条件、且下面 `plan` 实际返回 `READY_TO_START` 时，才能显式启动正式产线：

```powershell
python scripts/storyos_codex_managed.py run "episodes/00_独立篇/06_五十亩山地之后" --ack-real-production
```

该入口使用 `CODEX_MANAGED` + `STORY_OS_IMAGE_EXECUTOR=CODEX` 的原生 DAG，尊重 MySQL Model Policy、Review/Revision/Attempt Authority，完成图文 `PUBLISH_READY` 后停止，不创建视频。若不满足，输出结构化阻断码并保持 `00-06` 原貌。

## 只读检查的局限

最低 CLI 版本检查源于 OpenAI Codex `models.json` 2026-10-10 快照。它是客户端版本保护，不是实时模型目录、订阅可用性或图像生成能力证明。未知模型名保守阻断；需要先更新已审核的客户端版本映射。对已有 Episode 优先读取 MySQL 冻结策略；未冻结的新 Episode 使用现行配置作预备版本评估。不能因 `plan` 通行而跳过正式模型权限与图像提供者校验。
