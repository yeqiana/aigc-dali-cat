## 1. 三类配置的归属

| 类别 | 判据 | 例子 | 归属 |
|---|---|---|---|
| **生产规则参数** | 与部署环境无关，改它等于改产品行为 | `normalize.automatic_ratio_delta_max`、`production.max_inflight_images`、`runtime.review.*`、`timeout_policy` | ✅ `config/storyos.yaml`（本职，已在里面） |
| **部署拓扑** | 换机器/换环境就变 | `STORYOS_MYSQL_HOST/PORT/DB`、`STORYOS_REDIS_HOST/PORT/DB/TIMEOUT` | ⚠️ yaml 只放**仓库默认值**，运行时环境变量可覆盖 |
| **凭据** | 泄露即事故 | `STORYOS_MYSQL_PWD`、`STORYOS_REDIS_PASSWORD`、`OPENAI_API_KEY`、runner token | ❌ 只存在于运行时环境，任何形式都不进仓库 |

**凭据不能进 yaml 的三条硬约束：**

1. **git 历史不可撤销。** `config/storyos.yaml` 是 tracked 文件，一旦 commit，即使后续删除，
   密码仍永久留在历史里。当前是 `121.89.82.216:9000` 上的真实实例凭据。
2. **两个连接模块的 docstring 已把这条写成不变量**，不是随手写的默认值：
   - `platform/repository/mysql/mysql_connection.py:13` —「数据库密码（运行时从环境读取，**禁止写入仓库**）」
   - `platform/state/redis_connection.py:4` —「配置全部来自环境变量，**凭据不落盘**」
3. **依赖方向。** `platform/` 层当前对 yaml 是**零依赖**（全目录 grep 无 yaml / `storyos_config`
   引用）。让 `MySqlConnection` / `RedisConnection` 去读 `config/storyos.yaml`，等于让基础设施层
   反向依赖应用层配置。且 `tests/platform/test_*.py` 与 9 个 `scripts/phase9_*.py` 都是无参构造
   `RedisConnection()`，构造时读文件会把这些绑死在仓库布局上。

## 3. 本轮已收敛的部分

### 3.1 `config/storyos.yaml` 新增 `storage` 节

只放非敏感拓扑；凭据只写环境变量**名**：

```yaml
storage:
  mysql:
    host: 127.0.0.1
    port: 3306
    user: root
    database: story_os_runtime
    password_env: STORYOS_MYSQL_PWD
  redis:
    host: 127.0.0.1
    port: 6379
    db: 0
    timeout_seconds: 5
    password_env: STORYOS_REDIS_PASSWORD
```

### 3.2 `storyos_config.validate()` 新增 storage 契约位

`password_env` 必须匹配 `STORYOS_[A-Z0-9_]+`。**这条是「禁止把密码写进仓库」的机器化防线**：
任何看起来像密码字面量的值都匹配不上变量名格式，会在校验时 fail-fast，而不是静静地被提交。

### 3.3 新增应用层解析器 `episodes/_system/storage_config.py`

优先级**固定写死**（不提供配置开关）：**显式构造参数 > 环境变量 > yaml 默认值**。
导出 `mysql_connection_kwargs()` / `redis_connection_kwargs()` / `storage_summary()`。
`platform/` 层保持零 yaml 依赖——解析器负责读配置，再把结果**显式注入**连接对象。

### 3.4 已改写的连接构造点（9 处 / 6 个脚本）

| 脚本 | 位置 |
|---|---|
| `scripts/phase9_consistency_scan.py` | `build_checker()` 的 `MySqlConnection()` |
| `scripts/phase9_runtime_worker.py` | Redis 适配器、MySQL 连接 |
| `scripts/phase9_runtime_smoke.py` | B 组 MySQL、Redis、D 组 `RuntimeRepositoryProvider` 注入 |
| `scripts/phase9_canary_drill.py` | Redis 客户端、MySQL 连接 |
| `scripts/phase9_recovery_drill.py` | Redis 客户端 |
| `scripts/phase9_liveness_watchdog.py` | Redis 客户端 |

`phase9_runtime_smoke.py` 另有 `expected_db` 原先直接读 env，已改为读同一套解析结果，
避免 B 组（yaml 解析）与 D 组（env 默认）连到不同的库。

**行为等价性**：yaml 默认值与原先代码内硬编码默认值逐项相同，且环境变量优先级不变，
因此本轮对现网行为**零改变**，只是把「散落在代码里的默认值」收成一处可校验的声明。

**一处需要显式说明的生命周期修正**：`RuntimeRepositoryProvider` 只关闭「自己创建」的连接
（`runtime_repository_provider.py:190,221`）。改成注入后 `_owns_connection` 变为 `False`，
该连接不再被 provider 关闭——这是本轮改动**自己引入**的一个连接泄漏，已修正：
`phase9_runtime_smoke.py` 把注入的连接登记进 `ctx["provider_connection"]` 并在收尾统一关闭，
与原先「provider 自建自闭」的生命周期等价。

**验证方式说明（不要当作已验证）**：`tests/platform/test_phase9_runtime_smoke_script.py`
只覆盖离线 jsonl 路径，**不覆盖** mysql / dual 的 provider 装配与上述关闭路径。
该路径目前**只有代码审查、没有测试覆盖**。
