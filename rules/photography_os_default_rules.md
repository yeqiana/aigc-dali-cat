# Photography OS Default Rules

所有 Episode 默认视觉模式：

FIRST_PERSON_CASUAL_SNAPSHOT

规则：
1. 固定摄影者身份。
2. 图片必须像真实手机相册。
3. 优先表现正在发生的动作。
4. 禁止默认电影海报构图。
5. 保留真实摄影缺陷：
   - 偏构图
   - 遮挡
   - 手抖
   - 曝光变化

开头：
前3张建立人物关系和正常生活。

终审：
必须回答：
- 谁拍的？
- 为什么拍？
- 真人会保存这张照片吗？

## Story OS V2.2.8 Photography Continuity Defaults

### Camera Roster / Photographer Ownership
- 每个 Episode 必须明确 Primary Photographer。
- Secondary Photographer 允许存在，但切换必须有剧情/动作理由。
- 每张必须能解释：谁拍、相机为何在此人手里、摄影者站在哪里。
- 所有已知同行者都完整入镜时，必须存在真实摄影来源：第三同行者、交机、自拍、定时/固定机位。
- 禁止 Ghost Camera / 幽灵摄影机。

### First Person Is Logic, Not One Composition
- 第一人称是一种摄影逻辑，不是固定“手 + 手机 + 远景”构图。
- 手机不需要每张入镜。
- 10 张建议至少 4 类不同镜头。
- 禁止连续重复“手机前景 + 远处异常”。

### Moment + Save Reason
- 每张优先表现事情正在发生。
- 每张必须有 Save Reason：为什么这张会被留在手机相册。

### Opening Memory
- 前 3 张先建立人物关系、同行状态、正常生活和情感资产。
- 多人故事前 3 张至少 2 张体现人物关系或共同活动。
- 禁止前三张连续纯风景。
- 开场合影优先非正式：广角自拍、同行者随手拍、定时、反射；允许有人不看镜头/被裁切/正在拿东西。

### Camera Defect Physics
- 摄影缺陷必须有物理原因。
- 运动模糊 → 人/相机正在移动。
- 夜间噪点 → 低光/高 ISO/远摄。
- 反光 → 隔玻璃/镜面。
- 欠曝 → 可用光不足。
- 脱焦 → 突发抓拍/遮挡/移动。
- 禁止装饰性加糊、每张夜景同样糊。

### Visual Memory / Time Continuity
必须连续：
- 人物外观
- 衣服
- 车辆
- 随身物
- 路线/位置
- 天气
- 同场光线
- 已出现异常证据

时间必须自然推进；无明确时间跳转时禁止倒退。

### Screen Content Physics
出现手机屏幕、导航、地图、仪表盘、时间、聊天、相机 UI 时必须额外检查：
- 内容内部一致；
- 时间/路线与剧情一致；
- 屏幕方向、透视、反射物理成立；
- 禁止不可能的相机/UI 自指画面。
关键文字如果必须准确，应走后期文字校验/落版。

### Review Questions
1. 谁拍的？
2. 为什么此刻拍？
3. 摄影者在哪里？
4. 相机为什么在这个人手里？
5. 正在发生什么？
6. 为什么这张会被保存？
7. 有没有幽灵摄影机？
8. 和前后帧人物/衣服/车/时间/天气是否连续？
9. 摄影缺陷是否有真实物理原因？
10. 屏幕/UI 是否成立？
11. 是否又重复“手 + 手机 + 远景异常”？
