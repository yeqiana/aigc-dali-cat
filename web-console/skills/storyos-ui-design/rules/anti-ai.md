# Anti-AI Slop Rules (anti-ai.md)

本文件定义 StoryOS 界面严禁出现的“AI 模板坏味道 (AI Slop)”与审查门禁。
任何 Agent 在构建或审查 UI 时，若发现下列反模式，必须立即执行重构。

---

## 核心法则 (The Core Law)

> **一个页面如果：**
> **所有东西都很完整，所有东西都很平均，所有东西都有自己的盒子，所有东西都有自己的 Badge，所有东西都有自己的颜色。**
> **即使每个组件单独看都完全正确，整体也判定为高 AI Slop 风险（High Risk）。**
>
> 真正的工业级工控台依赖 **主次取舍、清晰的排版阶梯、非对称信息流、4px 间距节奏与 1px 细分割线**，而不是泛滥的容器包装。

---

## 20 项 Anti-AI 审查清单 (20-Point Checklist)

1. [ ] **Card / Panel 过多**：所有内容都必须塞进一个带边框的阴影方盒子里。
2. [ ] **标准化模板包裹**：每个模块千篇一律地呈现 `Icon + Title + Description + Badge + Border` 五件套。
3. [ ] **大量等宽、等高、等权重模块**：例如底部或中部直接出现 `1fr 1fr 1fr 1fr` 四个一模一样的大卡片。
4. [ ] **默认滥用 Bento Grid**：强行拼接不对称长短卡片，堆砌无业务价值的装饰插图。
5. [ ] **所有 KPI 独立 Card 化**：页面上方横向平铺 4~6 个大数字卡片，每个卡片独占巨大的无意义 padding。
6. [ ] **大面积铺展状态色**：整行由于 RUNNING 变为亮绿色背景，或整块卡片由于 BLOCKED 变成大红色块。
7. [ ] **紫蓝 AI Gradient 霓虹渐变**：使用 `from-purple-500 to-blue-500`、暗夜外发光、荧光色线条。
8. [ ] **滥用玻璃拟态 (Glassmorphism)**：使用半透明背景叠加 `backdrop-blur-md` 伪造高级质感。
9. [ ] **过多发光边框与 Glow 滤镜**：按钮或容器边缘带有扩散的光晕阴影。
10. [ ] **全组件泛滥大圆角**：容器使用 12px/16px/24px 大圆角，按钮使用 Pill 药丸椭圆。
11. [ ] **无意义的视觉 Gradient**：背景、文字或边框带有多色线性渐变。
12. [ ] **Generic Sidebar 模板化侧栏**：没有业务针对性的泛用图标排列与大面积空白。
13. [ ] **Generic SaaS Dashboard 营销感**：顶部出现欢迎标语、励志文案、产品功能宣传插图。
14. [ ] **用大量 Card 代替真正信息层级**：不愿使用 Table、内联列表或文字大小来区隔信息，只会新增盒子。
15. [ ] **所有模块视觉权重相同**：没有绝对的核心工作区，所有卡片在视觉上争抢眼球。
16. [ ] **每个区域都被完整盒子包起来**：缺少穿透式的通栏数据网格与开放式视线通道。
17. [ ] **存在无意义产品副标题**：如在“生产监控”下方加上“实时掌控您的自动化故事流转与全球生成资产”。
18. [ ] **存在看起来专业但不提供新信息的说明文案**：如“此模块用于展示任务的运行时间与状态变更”。
19. [ ] **状态色同时出现在多个区域抢注意力**：一屏之内同时闪烁多种高饱和度颜色，造成视疲劳。
20. [ ] **依赖装饰而不是排版与间距建立层级**：不用字号、字重、等宽数字、间距或 1px 分割线，而靠加粗边框和彩色背景。

---

## Non-Uniform Layout (非对称工业布局法则)

严禁在生产控制台中默认采用均质平分的栅格（如 `grid-cols-4` 均摊）。
不同业务模块的排障重要性截然不同，布局必须显式表达信息优先级：

- **主运行区 (Primary Operations Pipeline)**：应占据至少 60%~70% 的主要视线区域；
- **异常拦截与 Trace (Exception Interceptor & Event Stream)**：占据 30%~40% 的排错诊断侧轨；
- **比例推荐**：`1.5fr : 1.2fr : 1fr : 1fr` 或 `8 cols : 4 cols`，禁止机械平铺。
