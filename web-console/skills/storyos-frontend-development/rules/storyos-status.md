# Rule: StoryOS Status Contract

严禁各组件私自发明状态名称和状态颜色，统一遵循以下契约：

| 状态代码 | 视觉规范 | 业务语义 | 操作按钮约束 |
| :--- | :--- | :--- | :--- |
| **RUNNING** | 蓝色 `text-blue-400`, `bg-blue-500/15`, 脉冲圆点 | 正在推理、生成或执行 | 提供 [查看日志]、[取消当前任务] |
| **PASSED / COMPLETED** | 绿色 `text-emerald-400`, `bg-emerald-500/15` | 执行完毕，校验合格 | 提供 [查看大图]、[重新生成]；**严格禁止出现“跳过此帧”** |
| **QUEUED / WAITING** | 琥珀金/黄 `text-amber-400`, `bg-[#121214]` | 排队等待调度槽位 | 提供 [取消排队]、[置顶] |
| **RETRYING** | 橙色 `text-orange-400`, `bg-orange-500/20` | 自动退避重试中，明确标注尝试次数 | 提供 [立即手动重试]、[跳过此帧] |
| **BLOCKED** | 红色高亮 `text-red-400`, `bg-red-500/20`, 警示环 | 阻塞等待人工介入 | 提供 [手动接入干预]、[重置] |
| **FAILED** | 红色 `text-red-400`, `bg-red-500/10` | 最终失败 | 提供 [查看错误日志]、[重新运行] |
| **NOT_STARTED** | 灰调 `text-zinc-600`, `bg-[#101013]` | 未开始 | 仅展示占位 |

**原则**：绝不能单独依靠颜色区分状态，必须辅助以状态文字（如 `RETRY 2/3`、`IMAGE_GEN / 14s`、`PASSED`）。
所有高危/破坏性操作（重新生成、跳过、强制通过）必须具备二次确认弹窗。
