# 生产帧语义强制规范 V1.0

> Story OS V2.0.3.3 `Frame Semantic Enforcement` 的 active subordinate 规范。  
> 本文件只约束 **Batch 之后实际生成的图片是否忠实执行 Story Lock / Storyboard**，不建立新状态，不替代 `standards/制作规范_正式版.md`。

## 1. 目的

V2.0.3.2 已分别解决：

- Story Semantic Review：故事本身是否成立；
- Visual Profile Review：三张校准图是否真正继承 M00 / 当前视觉 Profile；
- deterministic subtitle layout：最终字幕排版是否稳定。

V2.0.3.3 补齐第四个责任面：

> **故事写对了、画风也对了，但最终每张图片有没有把锁定故事真的拍对。**

`Visual Profile PASS` 绝不等于 `Frame Semantic PASS`。

## 2. 唯一 Golden Path 不变

```text
Story Lock
→ Visual Lock
→ Batch
→ Frame Semantic Review
→ text audit
→ Release
```

机器状态仍然只有七个：

```text
IDEA_LOCKED
→ STORYBOARD_LOCKED
→ VISUAL_CALIBRATED
→ PRODUCTION_PASSED
→ PUBLISH_READY
→ PUBLISHED
→ DATA_REVIEWED
```

禁止新增第八状态、第二状态源或第二套生产工作流。

## 3. Fresh isolated critic

Batch 完成、所有 approved frame 已落盘后，必须使用：

```bash
python episodes/_system/frame_semantic_review.py run-critic <episode_dir> --attempt 1
```

Critic 必须：

- 新的 isolated Codex session；
- 一次看完整 approved frame set，而不是只读 prompt / ledger；
- 同时读取 Story Lock、Storyboard、Authenticity Card、Continuity Anchors；
- 不信任旧 PASS；
- 不允许自己修改图片、故事、分镜或 continuity contract；
- 将审查证据绑定到 **当前 approved asset SHA-256**。

Attempt 1 FAIL 时，只允许对被点名帧按既有 `max_content_repairs_per_frame=1` 返修，然后使用新的 isolated session：

```bash
python episodes/_system/frame_semantic_review.py run-critic <episode_dir> --attempt 2
```

Attempt 2 仍 FAIL：停止生产，不得伪造 review JSON，不得用 propagation score 覆盖。

## 4. 每帧硬项

每张最终 approved frame 都必须通过基础语义硬项；当 `meta/shot-progression-review.json` 为 schema_version=3 时，还必须通过导演层硬项。

1. `scene_storyboard_fidelity`：地点 / 动作 / 构图任务与分镜一致；
2. `story_beat_fidelity`：图片本身承载本帧叙事 beat；
3. `key_prop_fidelity`：关键道具的结构、材质、尺度、数量、状态一致；
4. `character_identity`：人物身份不漂移；
5. `wardrobe_continuity`：服装锚点与前后帧一致；
6. `pov_photographer_legality`：机位与拍摄者物理合法；
7. `spatial_continuity`：空间关系连续；
8. `temporal_continuity`：人物出入场、时间线连续；
9. `anomaly_readability`：本帧核心异常在像素里读得出来；
10. `caption_image_support`：字幕可补上下文，但不得凭空替图片制造核心证据；
11. `actual_information_gain`：实际相邻图片必须有信息增益，不得仅靠 storyboard 文本宣称不同。

schema_version=3 追加：

12. `shot_scale_fidelity`：实际景别与锁定 shot_scale 一致；
13. `scene_position_uniqueness_fidelity`：不同 `scene_position_id` 不能在实际成图中塌缩成明显重复机位；
14. `cinematic_structure_translation_fidelity`：只借锁定的镜头结构技巧，仍是故事内真实采集，不得变成具体电影剧照复刻；
15. `practical_lighting_design_fidelity`：实际光源、明暗关系与悬疑功能符合锁定 `lighting_design`，不得出现无来源电影灯；
16. `anomaly_concealment_fidelity`：声明镜面、水面/玻璃反射、雾、光影、屏幕、遮挡等载体时，实际像素必须真的形成该第二信息层。

任一项失败即该帧 FAIL。

## 5. 硬失败例

以下必须阻断 `PRODUCTION_PASSED`：

- 主角突然换性别、年龄、脸或核心服装；
- 人物按剧情已经离场，却在后续图片无解释重新出现；
- 第一人称拍摄者完整入镜，但 Authenticity Card 没有合法第二拍摄源 / 镜面 / 固定机位解释；
- 两只手都在操作道具，但没有合法拍摄来源；
- 分镜锁的是特殊关键道具，成图却用通用替代品；
- 字幕写“河歪了 / 红线对着烟囱 / 多张旧照片都有白弧”，但图片本身看不清这些关系；
- 结尾两张 storyboard 文字不同，但实际图片几乎重复；
- recovered / locked 资产只有旧 approval，没有与当前 SHA 绑定的 schema v2 Frame Semantic Review。

## 6. SHA 绑定与 recovered asset

V2.0.3.3 的 `meta/frame-reviews/NN.json` 使用 schema 2，至少绑定：

- `asset_path`
- `asset_sha256`
- `story_sha256`
- `storyboard_sha256`
- `visual_contract_sha256`
- fresh isolated critic provenance
- 11 个 hard checks

只要 approved asset SHA 发生变化，旧 review 自动失效。

> `Recovered locked approved candidate; previously reviewed` 不再是充分证据。

没有 **当前 SHA 的结构化 review**，不得恢复为 Production PASS。

## 7. 实际图片重复检测

`frame_semantic_review.py` 对最终 approved frame 执行 deterministic perceptual duplicate audit：

- 相邻帧近重复：硬失败；
- 非相邻帧几乎完全重复：硬失败；
- 更宽泛的“构图虽不同但信息仍重复”由 isolated critic 的 `actual_information_gain` 负责。

这条检查的是 **actual image**，不是 storyboard 描述。

## 8. Release closure

V2.0.3.3 的委托交付包在 build 前必须重新运行：

```text
frame semantic audit
+ machine_gate(PRODUCTION_PASSED)
```

交付 ZIP 必须携带：

- `meta/frame-semantic-review.json`
- `meta/frame-semantic-audit.json`
- `meta/frame-reviews/NN.json`
- `story-semantic-review.json`
- `visual-profile-review.json`
- `subtitle-layout-audit.json`
- `story-gates.json`
- `production-ledger.json`
- `release-manifest.json`

所有纳入包内的文件进入 `checksums.sha256`。

## 9. 版本一致性

任何 delegated delivery / release evidence 中出现的 `story_os_version` 必须读取：

```python
story_os_contract.story_os_version()
```

禁止硬编码旧版本，例如 `2.0.2`。

## 10. 一句话

> **V2.0.3.3 不再只证明“故事对、画风对、字幕对”，还必须证明“最终每张图片真的把锁定故事拍对”。**
