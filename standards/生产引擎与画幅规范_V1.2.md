# 生产引擎与画幅规范 V1.2

> 身份：`standards/制作规范_正式版.md` 的执行细则，不建立第二创作权威。  
> 目标：把“逐张生成、失败恢复、返修、锁图、发布资产”变成可追踪事务，避免提示词漂移、参考图漂移、技术失败误占返修次数和原图被覆盖。

## 0. 默认画幅（全局执行默认）

当用户、分镜、剧集 README、`release-manifest.json` 均**没有明确指定画幅**时：

- 默认比例：**4:5**
- 默认尺寸：**1080×1350 px**

明确指定时支持：

| 比例 | 标准尺寸 | 使用条件 |
|---|---:|---|
| **4:5** | **1080×1350** | **默认；未指定时自动采用** |
| 9:16 | 1080×1920 | 任务/分镜/manifest 明确指定时采用 |

规则：

1. 单篇进入正式分镜后画幅视为锁定；不得在同一正文中无剧情理由混用 4:5 与 9:16。
2. `release-manifest.json -> episode.aspect_ratio` 是该篇机器验收画幅事实；新篇初始化未传 `--aspect-ratio` 时写入 `4:5`。
3. 发布图必须精确匹配对应尺寸；不以黑边、白边、拉伸或模糊填充补比例。
4. 历史已锁定为 9:16 的剧集不追溯改成 4:5；继续生产时尊重原 manifest。
5. 网页 GPT / 其他生图交接若未写比例，Agent 必须补成 `竖版4:5，1080×1350`。
6. 画幅不是只约束发布图：`Frame Contract → Generation Request → RAW → Normalize → Approved → Release` 必须使用同一 Episode 级锁定比例。不得故意请求另一比例，再依赖后处理裁图修复。

## 1. Production Ledger 不得成为第二状态机

每篇正式生产可创建：

```text
meta/
├── episode-state.json        # 唯一剧集阶段事实源
├── release-manifest.json     # 发布事实 + 画幅事实
├── story-gates.json          # 门禁证据
└── production-ledger.json    # 逐帧生产事务；不保存剧集 stage
```

`production-ledger.json` 只回答：

- 这一帧用了什么 prompt / reference / capture profile；
- 哪次请求成功、哪次是技术失败；
- 当前候选是哪一张；
- 是否使用过唯一一次内容返修；
- 哪个资产被通过、提升、锁定；
- 生成指纹和 SHA-256 是否发生漂移。

它**不能**写入或覆盖 `current_state`。

## 2. 逐帧状态

```text
PENDING
→ GENERATING
→ ORIGINAL_READY
→ PASSED
→ LOCKED
```

内容失败分支：

```text
ORIGINAL_READY
→ CONTENT_FAILED
→ REPAIR_AUTHORIZED
→ REPAIRING
→ REPAIR_READY
→ PASSED | NEEDS_USER
```

技术失败分支：

```text
GENERATING / REPAIRING
→ TECH_FAILED
→ 原类型重试
```

### 硬规则

- `TECH_FAILED` 不消耗内容返修次数。
- 每帧最多 **1 次内容返修**。
- 返修必须显式进入 `REPAIR_AUTHORIZED`，不能看到失败就自动重画。
- 返修候选再次内容失败 → `NEEDS_USER`。
- 已锁图禁止被后续 promote 覆盖。

## 3. Generation Fingerprint

每次正式请求必须至少固化：

```text
frame
kind: original | repair
prompt_sha256
prompt_chars
prompt_bytes
capture_id
model
quality: high
canvas: aspect_ratio / width / height
references[]:
  path
  role
  kind: identity | prop | location | capture_style
  sha256
request_fingerprint
```

`model + quality + frame_contract_sha256` 必须在 generation request 中直接可审计。正式生产 Quality 固定为 `high`；后端不得静默降级。

`request_fingerprint` 对上述稳定字段做规范化 JSON 后计算 SHA-256。

当出现：

- 角色突然不像同一个人；
- 地点结构漂移；
- 第 20 张质感和前文不一致；
- 修图后底图莫名变化；

先对比 fingerprint / reference hash / prompt hash，再做视觉判断。

## 4. Prompt 硬预算

正式单镜 prompt 默认限制：

- 不超过 **260 字符**；
- 不超过 **900 UTF-8 bytes**。

单镜只写本镜新增内容：

- 一个拍摄事件；
- 一个受限机位；
- 1–2 个有原因的采集缺陷；
- 最多 4 个本镜排除项。

身份、地点、固定道具、共享采集规则优先通过结构化字段和 reference 固化，不在每张 prompt 重复堆几十条。

## 5. Reference 治理

正式请求默认：

- 0–1 张参考最常用；
- 最多 2 张；
- 每张必须登记 `role + kind + sha256`。

可用 kind：

```text
identity
prop
location
capture_style
```

技术重试不得为了“好生成”而：

- 删除身份参考；
- 换参考图；
- 偷改 prompt；
- 改 capture profile；
- 改画幅。

如确需改变，应视为新内容方案并留下新的 fingerprint。

## 6. 资产永不覆盖

建议每篇固定：

```text
production/
├── originals/        # 首轮生成原图
├── repairs/          # 内容返修图
├── approved/         # 审核通过后提升的不可变候选
├── publish/          # 真正发布版；可含后期字幕
└── contact-sheets/   # 总览联系表
```

原则：

- 原图永不被返修覆盖；
- 返修永不覆盖原图；
- `approved` 是内容通过的来源事实；
- `publish` 可以是 approved + 字幕等受控后期；正文画幅已在 Episode 级锁定，默认禁止以裁切修复比例；
- subtitle-only 必须继续使用 `story-gates.locks.assets` 的 SHA-256 门禁。

## 7. 批次管理

正式生产的含义是“同时在途图片最多 3 张”，不是等待固定三张整批完成。Scheduler 使用 `continuous_first_completed=true`：任一图片完成后立即补入下一张，Ledger 仍保持单写入者。审计批次可继续登记：

```text
batch_id
frames
started_at
ended_at
max_successes
summary
```

批次只是生产审计单位，不改变剧情状态。

高潮帧、封面候选、结尾 payoff 帧原则上应单独或小批处理，避免连续生成造成风格漂移未被及时发现。

## 8. 联系表

生成候选后应可用：

```bash
python episodes/_system/contact_sheet.py <episode_dir> --source candidate
```

审核通过后：

```bash
python episodes/_system/contact_sheet.py <episode_dir> --source approved
```

联系表只用于人工总览，不代替逐图原尺寸审查。

## 9. 命令示例

初始化（**未指定即 4:5 / 1080×1350**）：

```bash
python episodes/_system/production_ledger.py init <episode_dir>
```

显式 9:16：

```bash
python episodes/_system/production_ledger.py init <episode_dir> --aspect-ratio 9:16
```

登记首轮请求：

```bash
python episodes/_system/production_ledger.py begin <episode_dir> \
  --frame 01 \
  --capture-id phone_primary \
  --prompt-file workbench/prompts/01.txt \
  --reference assets/characters/a.png::protagonist::identity
```

技术失败：

```bash
python episodes/_system/production_ledger.py tech-fail <episode_dir> \
  --frame 01 --code timeout --message "image service timeout"
```

成功候选：

```bash
python episodes/_system/production_ledger.py success <episode_dir> \
  --frame 01 --path production/originals/01.png
```

内容审查：

```bash
python episodes/_system/production_ledger.py review <episode_dir> \
  --frame 01 --decision pass --notes "真实性/连续性通过"
```

通过后提升：

```bash
python episodes/_system/production_ledger.py promote <episode_dir> --frame 01
```

全篇审计：

```bash
python episodes/_system/production_ledger.py audit <episode_dir> --require-passed
```

## 10. 与 Story OS 门禁的关系

进入 `PRODUCTION_PASSED` 前，人工/多模态判断仍由主规范负责：

- 是否像真实私人记录；
- 人物、地点、道具是否连续；
- 高潮是否够强；
- 字幕是否自然；
- 图片与字幕是否互补。

Production Engine 只负责把这些结论对应的生产证据保存下来，不替代审美与剧情判断。

## 11. NP01 Normalize 技术标准化

Normalize 开启，但只负责技术整理，禁止偷偷重构画面：

| 条件 | 行为 |
|---|---|
| RAW 已是目标 PNG 且尺寸完全一致 | `NOOP`，仅复制到候选路径，不重新编码 |
| `ratio_delta ≤ 0.03` | 允许 Lanczos resize，不裁切 |
| `0.03 < ratio_delta ≤ 0.05` | `NORMALIZE_REVIEW`，暂停人工复核 |
| `ratio_delta > 0.05` | `ASPECT_RATIO_MISMATCH`，Reject；先查 Generation Request，再决定是否重生 |

- 正式输出 PNG；RAW 永久保留且不覆盖。
- 默认 Crop 禁止；`ImageOps.fit` 只允许显式异常兼容路径，不属于正式默认链路。
- Normalize 技术失败在本地重试；重试耗尽时保留 RAW 并阻断，不自动触发再次生图。
