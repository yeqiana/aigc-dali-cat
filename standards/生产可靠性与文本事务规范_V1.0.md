# 生产可靠性与文本事务规范 V1.0

> Story OS V1.7 从属执行细则。创作规则仍以 `standards/制作规范_正式版.md` 为唯一权威；阶段事实仍只来自 `meta/episode-state.json`。

## 1. 目标

本规范只解决三类工程问题，不新增创作状态机：

1. 生图调用发生网络、超时、后端、限流、无候选等技术失败时，不得污染内容返修次数；
2. 技术重试必须保持原请求指纹，禁止为“重试成功”静默改 prompt、model、capture profile 或 reference；
3. 已完成或已锁图片的剧集只修字幕/故事文字时，必须使用可备份、可 diff、可批准、可回滚的文字专修事务。

## 2. Transport Guard

正式生图请求先由 `production_ledger.py begin` 固化请求，再执行：

```bash
python episodes/_system/transport_guard.py preflight <episode_dir> <frame>
```

约束：

- 读取 `meta/production-ledger.json` 最新 attempt 的 `request_fingerprint`；
- 如果上一 attempt 是 `technical_failure`，本次 fingerprint 必须完全一致；
- 连续技术失败默认 3 次打开 circuit；`auth` 失败立即打开；
- circuit 打开后不得继续无脑重试，必须先修复传输问题；
- transport evidence 写入 `meta/transport-state.json`，它不是 stage source。

失败登记：

```bash
python episodes/_system/transport_guard.py failure <episode_dir> <frame> \
  --category network --message "..."
```

成功登记：

```bash
python episodes/_system/transport_guard.py success <episode_dir> <frame> --candidate <path>
```

## 3. Text Audit

字幕正文继续服从《字幕人话化与声音卡规范 V1.1》。机器审计只执行可验证硬项和 AI 腔警告，不自动改稿。

```bash
python episodes/_system/text_audit.py <episode_dir> --file <subtitles.yaml>
```

硬失败包括：

- 非静默帧字幕为空；
- 单帧字幕超过 48 字；
- 使用声音卡明确列入 `forbidden_technical_terms` 的术语。

人工警告包括：

- 连续三帧同一公式化开头；
- 连续三帧句长异常整齐；
- 整篇句长变化过小；
- 重复字幕；
- “不是……而是…… / 每次……都会…… / 直到……才…… / 这证明 / 这意味着”等高频 AI 句式；
- 声音卡关键字段缺失。

警告默认不阻断；需要把警告也作为 CI/人工门禁时使用 `--strict-warnings`。

## 4. Text Revision Transaction

只修文字时禁止直接修改锁定图片、reference、release manifest、production ledger、episode state 或 story gates。

开始事务：

```bash
python episodes/_system/text_revision.py start <episode_dir> \
  --file docs/最终文案.md \
  --file meta/subtitles.yaml \
  --note "只修字幕和发布文案"
```

开始时会：

- 备份所有明确登记的可编辑文件；
- 对 release manifest、生产 ledger、状态文件、批准/发布图片和 reference 资产做保护快照；
- 创建 `meta/text-revisions/<txid>/transaction.json`。

查看差异：

```bash
python episodes/_system/text_revision.py diff <episode_dir>
```

提交：

```bash
python episodes/_system/text_revision.py submit <episode_dir>
```

提交前必须确认保护资产 hash 未变化；YAML/TXT 字幕文件会自动执行 text audit。

用户明确批准后：

```bash
python episodes/_system/text_revision.py approve <episode_dir> --user-approved
```

不满意则：

```bash
python episodes/_system/text_revision.py revert <episode_dir> --reason "..."
```

文字事务不得推进或回退 `episode-state.json`。

## 5. 与 V1.6 的关系

V1.7 不改变七阶段：

`IDEA_LOCKED → STORYBOARD_LOCKED → VISUAL_CALIBRATED → PRODUCTION_PASSED → PUBLISH_READY → PUBLISHED → DATA_REVIEWED`

新增的 `transport-state.json` 与 `text-revisions/` 都只属于工程证据/事务，不是第二状态机。
