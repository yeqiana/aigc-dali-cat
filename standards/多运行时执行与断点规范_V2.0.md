# 多运行时执行与断点规范 V2.0

这是执行层规范，不是第二套创作规范。

Story OS 自动路由 `WORK > CODEX > WEB`。`WORK` 是 ChatGPT/Work + DevSpace 默认产品运行时；`CODEX` 仅在用户或调用方显式选择时启用；`WEB` 作为无本地工作区能力时的产品运行时。三个 runtime 共用主规范、M00、真实性、字幕、Capture Profile、回归库与 `<episode>/meta/episode-state.json`。WORK/WEB 不得因为本机存在 `codex.exe`、缺少 API Key 或某项产品能力缺失而静默回退到本地 Codex。

严禁创建第二套 runtime stage。

用户明确说“全自动执行 / 一次做完 / 做到最终交付 / 不要每步问我”时，视为 `continuous_execution_authorized=true`。这允许执行器自主继续 Golden Path、自审和最多一次内容返修，但不等于用户亲眼审过每张图。

统一 checkpoint：`<episode>/meta/runtime-checkpoint.json`。它是恢复证据，不是 stage。

必须暂停：权限/登录/安全确认、仓库完全缺失必要事实、不可消解硬冲突、一次内容返修后仍失败且继续会破坏已锁剧情。
