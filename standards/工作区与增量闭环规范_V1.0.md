# Story OS 工作区与增量闭环规范 V1.0

适用版本：Story OS V2.0.3.4+

## 1. 原则

- Git 管规则、故事文本、机器证据与 SHA，不承载大规模生成媒体。
- Episode 管故事事实；本地 `media/` 管像素资产；`meta/media-index.json` 把两者绑定。
- 已通过且输入指纹未变化的节点必须复用，不得为了“更保险”无条件重跑模型 Critic。
- 默认走最小闭环；只有 Story / Storyboard / Visual Contract 变化、脏帧比例过高或局部证据不足时升级 Full Review。

## 2. 新篇目录

```text
<episode>/
├─ story/                  # Story Lock / storyboard / visual lock / publish copy
├─ meta/                   # stage / gates / ledger / reviews / media-index
├─ assets/
│  ├─ characters/          # 可入 Git
│  └─ references/          # 本地媒体，不入 Git
├─ media/                  # 本地媒体，不入 Git
│  ├─ calibration/
│  ├─ raw/
│  ├─ candidates/
│  ├─ approved/
│  ├─ publish/
│  ├─ review/
│  └─ archive/
└─ release/                # cover / final zip，本地，不入 Git
```

历史剧集不要求一次性改写文本目录。`PRODUCTION_PASSED / PUBLISH_READY / PUBLISHED / DATA_REVIEWED` 或已有 `delegated-release.json` 的剧集属于**证据冻结剧集**：旧媒体路径已经进入 SHA / release evidence，不做物理搬迁，只继续本地忽略。只有尚未形成冻结证据、重新进入制作的剧集，才允许由 `media_workspace.py` 安全迁移。

## 3. 增量帧审核

第一次完整生产：

```text
FULL_FRAME_SET → baseline
```

之后只要 Story / Storyboard / Visual Contract 未变化：

```text
asset/caption fingerprint diff
→ dirty roots
→ dirty ± 1 context
→ 结尾高风险帧 dirty ± 2
→ INCREMENTAL_CONTEXT_SET critic
→ cheap full-set SHA + perceptual duplicate audit
```

当脏帧 > 25% 或 Story/Storyboard/Visual Contract 改变时，自动升级 `FULL_FRAME_SET`。

## 4. 证据复用

允许复用必须同时满足：

- approved asset SHA 未变化；
- Story / Storyboard / Visual Contract hash 未变化；
- 当前帧 caption fingerprint 未变化；
- 现有 review 是独立 Critic 的 PASS；
- 全局近重复检测仍通过。

否则该帧进入 dirty set。

## 5. 本地媒体迁移

迁移只处理 `git ls-files --others -i --exclude-standard` 能看到的本地忽略媒体，并且只自动迁移存在 `meta/episode-state.json` 的 Story OS 管理剧集。

流程固定：

```text
inventory → SHA → copy → SHA verify → rewrite tracked references → verify → remove old path
```

失败时恢复已改 tracked references，并尽力恢复源文件。历史未纳管媒体只进入 inventory，不自动移动。
