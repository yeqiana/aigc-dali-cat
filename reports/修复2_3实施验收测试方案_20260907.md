## 7. B1 主循环合并判定（D5 退出条件已触发，2026-09-07）

完成共享原语切换后对两个主循环做了合并可行性复核，结论：主循环不合并，保留两条 lane 实现，共享原语继续单真源演进。依据（均为实施时源码取证，不是推断）：

1. 事件处理形态不同：image lane 每个运行行独立 worker 事件流（IMAGE_SUCCESS/IMAGE_FAILED 逐行终结）；batch lane 把同批 5 行绑定到一个 native batch task（asyncio.shield 跨行共享同一任务结果，行级 handler 只是消费方），同一 handler 无法无回归表达两种流。
2. provider 分派粒度不同：batch 走 image_provider_runtime.select_batch_provider 的三级 provider 选择（openai_images_api / codex_subscription / product_runtime_image），并有 capability probe 与 verified_image_lane 门槛、_defer_scout 屏障；image lane 只按 WORK/WEB 与 CODEX runtime 分派，滚动审查独立执行。
3. 收尾账本不同：batch 结束后统一 capability_probe.record、batch 性能写盘、技术失败时 adaptive_parallel 递减、Fast Scout 在 barrier terminal 后；image lane 按状态集直接返回 0/20/21/22/24，无同构收尾步骤。
4. 退出码契约不同：batch 使用 SUCCESS=0 / RECOVERABLE_FAILURE=21 / HUMAN_REQUIRED=22 / CAPABILITY_WAIT=24；image lane 的 22 语义还覆盖 blocked/interrupted_unknown 判定。
