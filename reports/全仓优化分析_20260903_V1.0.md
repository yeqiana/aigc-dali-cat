## 0. 总体判断（TL;DR）

架构方向正确：配置驱动 fail-fast（`storyos_config.py` 真实消费 `config/storyos.yaml` / `config/index.yaml`）、契约分层清晰、V2.4 batch 运行时分层干净（worker 复用 `codex_subscription_image`、repair 有探针式背压）、manifest/runtimes 引用路径全部存在、无 import 环、无 TODO 残留、`__pycache__`/`.idea` 均未入库。

**问题集中在两类**：
1. **版本迭代堆叠出的"同概念多实现"**——同一评分表/编译器/调度逻辑多份拷贝，改一处会悄悄带偏另一条产线；
2. **内容与文档的手工漂移**——4 份根文档手工同步已分叉、两套规范注册表、跨系列角色矛盾、多集双轨并行。

**最高风险三处（改配置/改一处代码会静默影响另一条产线）**：
1. risk_priority 评分表双份（调度与 V2.4 返修门控各自维护）；
2. V2.4 新代码（batch/repair/DAG）零 CI 保护 + 3 处"print PASS"假自测；
3. 死配置静默回落（`or 80`、`or 1`）违反 `storyos.yaml:11` 自己声明的 fail-fast 原则。

## 2. 🟡 B 级：中价值收敛项

1. **CI 平台与项目现实脱节**：`runs-on: ubuntu-latest` + Python 仅 3.12 无矩阵，而项目是 Windows-first（PowerShell 冒烟、CRLF 策略、desktop provider）——Windows 侧语法/路径问题永远无人把关。建议加 `windows-latest + 3.12` job 跑 compileall + tests/system。
