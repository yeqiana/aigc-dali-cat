### 中断根因与当前处理

1. **真实图片通道被全局网关覆盖**：本机 Codex 的 `openai_base_url` 指向 OpenCodex 本地网关。独立图片探针得到 rc=0 和文本，没有有效图片；同一 `gpt-5.6-luna / medium` 控制器，仅在图片子进程覆盖原生订阅 provider/address 后，77.62 秒生成真实 PNG。现已写入 `codex_subscription_image.controller_args()`；不修改全局配置。详见 [本次修复验证记录](全仓优化修复验证_20260907.md)。图片探针不是正式 Episode 门禁证据。
2. **错误被过度升级或吞掉**：Runner 现在先解释结构化退出码，再使用旧文本分类。技术失败有界重试；未知失败先有界重试；HOST_WAIT 不冒充人工审批，也不空转。无进度的 rc=0 循环达到阈值后记录能力等待。
3. **调度器不能把局部失败当整批失败或成功**：有独立可运行帧时优先继续；失败帧单独重试；Ledger begin 拒绝的帧不送图片 worker；已有候选但提交失败保留候选与 open attempt，阻止重复出图。无实际输出不能记 generated。
4. **并发与恢复事实闭环（P0）**：Runner 和两个图片调度入口使用 OS 进程锁，Queue 与 Ledger 改为原子落盘。每个 worker 现在持久记录 transaction id、调度进程 PID、预期输出/日志、backend 调用点和终态 result/receipt；启动时按 Queue、Ledger 和 lifecycle 三方对账。Ledger 已成功但 Queue 未落盘、以及 worker 已写入成功终态但 Ledger 未提交的情况会安全补写；已记录失败会关闭为技术失败；没有终态 receipt 的在途调用标为 `interrupted_unknown`，绝不自动重生或伪造 PASS。该状态不会阻止没有依赖关系的兄弟帧继续。
