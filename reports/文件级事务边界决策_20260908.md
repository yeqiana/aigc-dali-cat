# Story OS 文件级事务边界决策（2026-09-08）

范围：全仓优化第 2/3 类修复 B11（S3.5）。本文件只记录已接受的工程语义与边界，不引入新状态机，不改动 episode-state 唯一阶段权威。

## 结论

Queue / Ledger / worker lifecycle 之间的提交采用 **journal + 启动对账 + 有界 OS 锁 + 原子落盘** 作为正式接受的文件级事务语义；**不引入数据库**，也不把正式 Episode stage 纳入该文件事务。

## 接受的边界与兜底

1. Queue 与 Ledger 不是单次原子提交：以生产恢复模块（production_recovery）在持锁条件下按 Queue、Ledger、worker lifecycle、候选文件四方证据对账；可证明成功/失败才自动落盘。
2. 无终态 receipt 的在途调用保持 `interrupted_unknown`，不自动重生、不冒充 PASS；证据处理后由调度方决定重试。
3. 锁语义：OS advisory 文件锁（进程被杀由内核释放，锁 inode 常驻防双锁）；调度运行期间直接写 Queue 抛 `QUEUE_MUTATION_BUSY`；获取锁为非阻塞尝试，无自旋等待。
4. lifecycle/journal 缺失或损坏一律视为“无该证据”，按 pre-worker（可重试技术失败）或 UNKNOWN（不自动重生）处理，绝不当成功证据。
5. Queue 与 Ledger 双 stale/不一致（如 queue=running 而 ledger=PENDING 且无 BEGIN_PREPARED 证据）→ `QUEUE_LEDGER_MISMATCH` → `interrupted_unknown`。

## 对应证据与用例

- 实现：`episodes/_system/production_recovery.py`、`runtime_atomic_store.py`（原子写）、`runner_state_store.py`（OS 锁）、scheduler_core 队列事务。
- 既有对账回归：tests/system/test_runtime_recovery.py（unknown inflight、Ledger ready 回放、worker success 回放、pre-worker 重试、锁互斥/释放等 22 项口径）。
- 本批补齐缺口用例（tests/system/test_runtime_recovery.py）：
  - `test_corrupt_worker_lifecycle_never_counts_as_success`：lifecycle 损坏按缺失处理，可重试技术失败而非成功；
  - `test_double_stale_queue_ledger_stays_unknown`：双 stale 只落 `interrupted_unknown`，不自动恢复。
  - `test_corrupt_commit_journal_never_forges_success_or_blocks_reconcile`（86da86b 后补）：commit journal 损坏视为无证据、按可重试技术失败处理，reconcile 不崩溃、不因 journal 冒充成功，并重写为合法 JSON 保留当次 transaction；
