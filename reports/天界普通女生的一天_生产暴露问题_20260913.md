## W-35 纯日常题材被异常传播核规则误伤（P0）

### 暴露现象

Story OS 已支持 `daily_life`，`shot_progression_gate.py` 也允许 `anomaly_applicable=false`，但 V2.5+ 的 `story_review.py` 与 `propagation_core_gate.py` 仍默认要求：

- core anomaly
- anomaly rule
- trigger
- abnormal response
- visible consequence

本集明确要求“纯日常、无恐怖、无调查、无探秘、无异常”。若按旧规则继续，会为了过 Gate 被迫给生活题材硬塞异常，违反用户约束和题材定义。

### 修复

已做最小兼容修复：

1. `propagation_core_gate.py`
   - 明确 `anomaly_applicable=false` 且有具体原因时，纯日常题材可不强制异常 Propagation Core。
   - 异常题材原规则保持不变。
2. `story_review.py`
   - 对明确无异常 Episode 增加 ordinary-life override。
   - Critic 改为审查生活线、关系推进、因果/节奏、信息增量、视觉峰值和结尾回收，并禁止为了 schema 造异常。
3. `concept_ambition.py`
   - 对纯日常题材，Ambition 改为评估世界尺度、生活反差、关系密度、无字幕视觉吸引力，不允许为了 concept_voltage 增加恐怖/异常/调查。

### 暴露

## W-41 Baseline PASS 未同步 approved_asset（P0）

### 暴露

新增单测锁定 `review -> promote` 调用顺序。

## W-45 Authority Refresh 与 Incremental / PREIMAGE Recovery 状态不兼容（P0）

### 暴露

M04 天界普通居民生活档案及人物/Frame Contract 等上游权威重新派生后，Visual Lock 的 `01 / 05 / 16 / 17` 被正确标记为 `AUTHORITY_REFRESH_AUTHORIZED`，要求按新权威重新生成且不消耗普通内容返修额度。但恢复链存在四层不兼容：

1. `incremental_frame_review.py` 只接受 `PASSED / LOCKED`，把合法的 `AUTHORITY_REFRESH_AUTHORIZED` 当成坏数据，直接抛 `ValueError`。
2. `PREIMAGE_VERIFY` 这类纯确定性校验/重建仍被 Runtime DAG 发成 WORK Host Action，造成无意义 `HOST_WAIT`。
3. `product_runtime_adapter.next_host_step()` 只检查 Frame Contract index 文件是否存在，没有验证合同是否仍与当前权威 SHA 一致，因此 stale index 被误判为可直接 VERIFY。
4. 更深一层，旧 `PREIMAGE_COMMITTED_SNAPSHOT` 也可能已 stale；此时直接重编 Frame Contract 会被正确拒绝，恢复顺序必须先回到 fresh PREIMAGE task set，而不能硬刷新 derived cache。
5. Runtime DAG 已正确要求 fresh PREIMAGE 后，`next_action` 仍可能因 Ledger 中存在 `AUTHORITY_REFRESH_AUTHORIZED` 而优先返回 `REFRESH_AUTHORITY_IMAGES`；连续 Host Loop 会因此绕过 fresh PREIMAGE，形成旧权威图片刷新与新权威重建的竞态。

### 修复

- `incremental_frame_review.py`
  - 新增 unfinished ledger 识别；最终语义 Review 不再消费中间生产态。
  - `AUTHORITY_REFRESH_AUTHORIZED` 明确派生为 `AWAITING_AUTHORITY_REFRESH`，并保留 `authority_refresh_frames`、全部 pending 状态与原因。
  - `AWAITING_AUTHORITY_REFRESH / AWAITING_PRODUCTION` 不启动 Final Critic。
- `product_runtime_adapter.py`
  - `next_host_step()` 同时检查 PREIMAGE committed snapshot 新鲜度与 `frame_contract.verify_all()`。
  - stale committed snapshot → `PREIMAGE_TASK_SET`。
  - committed snapshot 有效但 Frame Contract stale/missing → `PREIMAGE_FRAME_CONTRACT_COMPILE`。
  - Frame Contract 有效但 handoff stale → `PREIMAGE_VERIFY`。
  - `PREIMAGE_VERIFY / PREIMAGE_FRAME_CONTRACT_COMPILE` 的历史 Host Request 可在 canonical evidence 已有效时 reconcile，不永久占用 current pointer。
- `runtime_dag.py`
  - 仅把 `PREIMAGE_FRAME_CONTRACT_COMPILE / PREIMAGE_VERIFY` 两类无模型确定性动作留在本地执行。
  - 真正需要模型生成候选的 `PREIMAGE_TASK_SET` 继续保持 WORK + DevSpace Host 边界，不静默交给 Codex，也不伪造候选。
- `next_action.py`
  - `STORYBOARD_LOCKED` 且 PREIMAGE authority/handoff stale 时，canonical PREIMAGE freshness barrier 优先于 Production Queue。
  - 此时统一返回 `PREIMAGE_COMPILE` 并携带真实 `preimage_step`，禁止 `AUTHORITY_REFRESH_AUTHORIZED`、技术重试或其他图片动作抢跑。
  - 只有 handoff 已重新验证后，Queue/Authority Refresh 图片路径才恢复正常优先级。
